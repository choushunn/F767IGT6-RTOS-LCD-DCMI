# 状态优先人脸授权界面设计

## 状态

已由用户确认，进入实现。

## 目标

将 1024x600 屏幕分成无间隙的两块：

- 左侧 424x600：状态优先的人脸授权面板。
- 右侧 600x600：OV2640 实时画面，完整占据屏幕剩余区域。

主目标是让用户不看说明句也能判断“现在是否允许上机、下一条动作是什么”。界面文字只保留操作和异常所必需的信息。

## 非目标

- 不接入真实人脸识别算法。
- 不新增复杂动画、图表或装饰性遮罩。
- 不在正常情况下持续显示摄像头、触摸、网络等辅助状态文字。
- 不为了适配尺寸而压缩摄像头画面，也不保留上下留白。

## 布局

```text
0                         424                    1024
┌─────────────────────────┬────────────────────────┐
│ A-01              ●在线 │                        │
│                         │                        │
│                         │                        │
│ 身份核验                │      600x600           │
│ 等待验证                │      实时摄像头         │
│                         │                        │
│ 当前步骤：人脸采集       │                        │
│                         │                        │
│ [       开始验证      ] │                        │
│                 ●  ●    │                        │
└─────────────────────────┴────────────────────────┘
                           424..1024
```

### 左侧面板

1. 顶部身份区：只保留设备编号和在线状态，不再显示产品或方案名称。
2. 主状态区：只显示“等待验证 / 正在核验 / 验证通过 / 验证未通过”等高权重状态。正常状态不显示长说明句；异常时才显示一条可执行提示。
3. 当前步骤区：同一时间只显示一个人脸采集、身份比对或上机授权步骤。步骤完成后由状态机切换到下一项，不显示完整三阶段轨道。
4. 主要动作：底部整宽按钮，文字随状态变化为“开始验证 / 保持不动 / 重新验证”。
5. 设备健康：正常时只显示两个低干扰状态灯；异常时在对应状态灯附近显示简短故障文字。

### 右侧摄像头

- 窗口固定为 `x=424..1024`、`y=0..600`，宽高 600x600。
- 移除当前 12px 上下留白和 UI/相机之间的 16px 空隙。
- 正常情况下不叠加标题、边框或说明文字，让实时画面本身承担主要信息。

## 方案选择

考虑了两种结构：

- 状态优先：大字状态、单步提示、单一动作。信息更少，适合现场快速授权。
- 流程优先：以三阶段纵向流程为主。解释更完整，但文字和层级仍偏多。

用户选择“状态优先”。实现以状态优先方案为准。

## 技术影响

### 显示配置

```text
DISPLAY_LVGL_W      = 424
DISPLAY_LVGL_H      = 600
DISPLAY_CAMERA_W    = 600
DISPLAY_CAMERA_H    = 600
DISPLAY_CAMERA_X0   = 424
DISPLAY_CAMERA_Y0   = 0
```

600x600 RGB565 每帧约 720000B。现有三块相机帧缓冲各间隔 786432B，容量足够，地址无需调整。

### 摄像头采集

- OV2640 图像窗口与输出尺寸改为 600x600，保持 1:1，不做缩放。
- 一行 600 像素 = 1200B = 300 个 32 位字。
- 每块仍使用 24 行：7200 个字/块，25 块/帧，均低于 NDTR 的 16 位上限。
- 保持已验证的 DMA FIFO Full、内存 INCR4 和 NORMAL 逐块续排。
- 1200B 行宽不是 64B 整数倍，但每块总字节数和目标地址仍满足 DMA 对齐要求；实机必须检查 `fu/terr/fe`。

### 状态与交互

- 保留 `FACE_UI_DEMO_FLOW=1`，继续明确这是 UI 演示流程。
- 状态颜色继续使用安全黄、通行绿、拒绝红。
- 删除完整流程轨道、重复说明、结果标题、状态行标题和底部三项文字。
- 同一时间只显示当前步骤：人脸采集 → 身份比对 → 上机授权；上一步完成后才替换为下一步。

## 验证

1. UI 左边界为 0，右边界为 424；相机左边界为 424，右边界为 1024，无覆盖和空隙。
2. 摄像头画面为 600x600，无上下留白。
3. 串口 `[cam] sensor out=600x600`、块计数为 7200 字 x 25 块/帧。
4. 连续运行至少 30 秒，`pub` 持续增长，无持续 `fe/eovr/desync` 增长，`fu/terr` 稳定。
5. 状态文字、按钮和触摸区域在 424x600 内无重叠。
6. 摄像头断开时不依赖常驻说明文字，界面能明确进入错误状态并保留重试入口。
