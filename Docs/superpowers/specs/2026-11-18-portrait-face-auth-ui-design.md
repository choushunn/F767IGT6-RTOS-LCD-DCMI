# 竖屏人脸验证界面设计

## 状态

用户已确认布局方向。UI 设计层已完成，并按实机反馈补入 270° 显示方向、512×512 按需相机预览和拍照冻结；真实识别算法仍不在本阶段范围。

## 目标

将界面改为物理面板旋转 270° 后的 600×1024 竖屏画面：

- 相机预览态在 `x=44, y=44` 放置 512×512 预览/冻结照片区域，四周留有空白。
- 待机时顶部使用 600×600 彩条滚动占位，进入验证流程后隐藏，后续可替换为动态广告图片。
- 下方显示当前状态、环形验证进度、三个顺序步骤和唯一主按钮。
- 待机时不显示实时摄像头画面。
- 保留 `FACE_UI_DEMO_FLOW=1`，明确当前仍是 UI 演示流程。

## 非目标

- 本阶段不接入真实人脸检测、比对或上机联锁。
- 不恢复“高空作业吊篮”等品牌文字。
- 不同时显示三个同等重要的操作按钮。

## 交互流程

| 状态 | 状态标题 | 主按钮 | 可执行操作 |
|------|----------|--------|------------|
| IDLE | 等待上机验证 | 开始上机 | 进入预览步骤 |
| PREVIEW | 请正视摄像头 | 开始拍照 | 冻结当前完整帧 |
| PHOTO_READY | 确认抓拍 | 开始验证 / 重拍 | 确认抓拍后验证，或重新启动预览拍照 |
| SCANNING | 身份比对 / 上机授权 | 验证中 | 禁止重复触发 |
| VERIFIED | 授权通过 | 重新验证 | 返回待机 |
| REJECTED | 验证未通过 | 重新验证 | 返回待机 |

底部步骤行同时承担位置导航，但只有当前步骤使用安全黄色高亮，已经过的步骤使用通行绿，未到达步骤保持弱化。主按钮仍只提供当前唯一动作。

环形进度只在验证流程中承载主要进度反馈。待机、预览和结果状态保持同一个几何位置，避免界面跳动。

## 显示方向

物理面板仍是 1024×600。LVGL 逻辑显示创建为原生 1024×600，再应用实机确认的 270° 旋转，使其逻辑坐标为 600×1024。

- LVGL flush 使用 `lv_display_rotate_area()` 和 `lv_draw_rotate()` 写入原生横向 SDRAM 帧缓冲。
- 触摸驱动上报原始 1024×600 坐标，由 LVGL v9 输入层按显示旋转自动转换成 600×1024 逻辑坐标。
- LTDC 图层 1 本阶段覆盖全屏，原生窗口仍为 1024×600。
- LTDC 图层 2 在 UI 设计阶段保持关闭；本阶段不调用相机的首帧图层使能路径。

270° 方向由实机“上下反了”的反馈确认；显示与 LVGL 输入层自动坐标转换必须保持同向。

## 方案选择

考虑过三种方案：

- 继续使用 424/600 横向分栏：改动最少，但不符合用户确认的竖屏现场布局。
- 在横向面板内只做纵向排列：无需旋转，但 512×512 预览、环形进度和底部流程无法同时保持清晰比例。
- 物理旋转后使用 600×1024 逻辑画布：比例最合适，用户已选择。代价是 LVGL flush 和触摸必须成对做坐标转换。

## 技术与验证约束

- 不改变 LTDC 面板时序和像素时钟。
- OV2640 输出调整为 512×512，128 行/块、4 块/帧；点击“开始上机”才启动采集。
- 新增中文“拍照”等字形必须重新生成 14px、24px 字体，不能依赖系统字体回退。
- 本阶段完成静态检查和构建检查，最终显示方向、触摸命中与画面稳定性必须由用户实机验证。
