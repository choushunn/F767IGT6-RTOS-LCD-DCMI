# DCMI 摄像头模块方案（OV2640 / 按行 DMA / LTDC 第二图层）

> **前提**：FreeRTOS 任务框架、UART 打印接口（`AppUart_Printf`）、LVGL 显示与左侧人脸授权界面已接入（见《01.FreeRTOS移植方案.md》《02.LVGL移植方案.md》）。
> 本文是 LVGL 基础界面验收后的下一步，只覆盖 DCMI 摄像头采集与显示；触摸与输入见《03.触摸移植方案.md》。
> 引脚分配见《实验46 照相机实验_引脚配置分析.md》。

## 1. 概述

> **当前状态（2026-11-18 联调中）**：已依据串口日志、历史 SWD 显存转储和正点原子 OV2640
> 参考序列完成两项软件修正：`0xDA` 恢复为 RGB565 低字节先输出的 `0x09`；DMA 从本板会

| 项目 | 说明 |
|------|------|
| 传感器 | OV2640（SCCB 配置；是否自带 24MHz 晶振待确认，见 §3.9） |
| 输出 | 600×600，RGB565，**窗口=输出 1:1（不缩放）**；DSP image size 只有 800×600，窗口必须 ≤ 该值 |

| 传输 | DMA2_Stream1，**NORMAL 模式逐块续排**，24 行一块（NDTR=7200 字/块），TC 中断重装 `M0AR/NDTR` 后重新使能 |
| 帧缓冲 | 外部 SDRAM **三块**：`0xC0140000`（FB0）、`0xC0200000`（FB1）、`0xC02C0000`（FB2） |

| 刷新节奏 | 换帧在 DMA 块完成中断内完成（第 25 块传完即一帧，切 CFBAR）；LVGL 定时器 40ms 只做统计、首帧使能与错位重排 |

代码位置：`App/camera/`（`app_camera` 采集与显示、`ov2640` 传感器、`sccb` 控制总线、`pcf8574` 扩展 IO、`camera_util` 微秒延时）。

## 2. 数据通路

- **采集**：OV2640 →（DCMI 8 位并口）→ DMA2_Stream1（`NDTR = 24 行共 7200 个 32 位字`，直接写入相机帧缓冲）。DMA 使用 NORMAL 模式，每块 TC 中断立即重装下一块 `M0AR/NDTR` 并重新使能 → 累计到 25 块即一帧（32 位原子包：bit[1:0] 为缓冲序号 0~2，高位为帧序号）。CPU 不参与像素二次拷贝。
- **显示**：最新完整帧 → LTDC 第二个图层硬件扫描；**发布与换帧都在 DMA 块完成中断内完成**（只改 `CFBAR` 并置 `LTDC_SRCR_VBR`），垂直消隐期生效。LVGL 不搬运、不绘制任何相机像素。
- **三缓冲**：写入目标按 0→1→2→0 轮换，保证 DMA 写入的缓冲既不是刚发布的那块，也不是 LTDC 正在扫描的那块（双缓冲必现撕裂，见 §3.6）。
- **边界**：本文只覆盖相机采集与显示；其他任务与本模块共享任务调度与 SDRAM 总线，临界区约束见 §3.8。

## 3. 摄像头

### 3.1 上电、复位与控制

| 信号 | 引脚 | 说明 |
|------|------|------|
| PWDN | PCF8574 P2（软件 I2C：SCL=PH4 / SDA=PH5，7 位地址 0x20） | 低电平上电；先保持高电平掉电，再清零 |
| RESET | PA15 | 低电平复位，释放后延时再访问 SCCB |
| SCCB SCL / SDA | PB4 / PB3 | 软件时序；SCL 推挽输出、SDA 开漏输出（可读回电平） |
| XCLK | PA8 | **不使用**（模组自带晶振；`gpio.c` 仍把它配成输出并驱低，属未使用引脚） |
| 蜂鸣器 BEEP | PCF8574 P0（与 PWDN 同一颗扩展 IO） | 低电平驱动响；`PCF8574_WriteBit()` 是读-改-写，写 P0 不会改变 P2 的 PWDN 电平 |

> PA15 / PB3 / PB4 是 JTAG 专用引脚，本工程使用 SWD 调试，可安全复用；若改为 JTAG 调试会产生冲突。

初始化顺序：PCF8574 配置并使 PWDN 保持高电平（掉电）→ OV2640 RST 拉低 20ms → PWDN 清零上电 → 5ms → RST 释放 → 20ms → SCCB 引脚初始化 → 读 manufacturer ID `0x7FA2` 与 product ID `0x2642` → 写入 UXGA 初始化表 → `OV2640_RGB565_Mode()` → `OV2640_ImageWin_Set(500, 300, 600, 600)` 中心 1:1 裁切 → `OV2640_OutSize_Set(600, 600)` → `OV2640_SetMirrorFlip(CAM_MIRROR_H, CAM_FLIP_V)` → DCMI 重配 → DMA 排流 → 置 `DCMI_CR_CAPTURE`。

> **画面方向**：OV2640 在 Sensor bank 的 `0x04` 寄存器中控制方向，bit[7] 为水平镜像、bit[6] 为垂直翻转。开关集中在 `app_camera.h` 的 `CAM_MIRROR_H` / `CAM_FLIP_V`，初始化完成后串口打印 `[cam] mirror=.. flip=..` 便于核对。

> OV2640 使用 8 位寄存器地址，不能复用 OV5640 的 16 位寄存器读写函数。`0xFF` 是 DSP/Sensor 寄存器组选择；图像窗口写 `0x51~0x57`，最终输出尺寸写 `0x5A~0x5C`，两者顺序不能颠倒。

### 3.2 DCMI / DMA 配置

| 项目 | 默认/基线 | 驱动实际 | 原因 |
|------|---------------|----------------|------|
| PCKPolarity | FALLING | **RISING** | 与模组实测及参考例程一致；FALLING 会在错误的边沿采样 |
| DCMI 数据/同步 GPIO | NOPULL + Low speed | **PULLUP + Very High** | Low speed 无法满足 PCLK 频率 |
| DMA2_Stream1 中断优先级 | 0 | **2** | 0 会强烈抢占 SysTick/TIM7 时基；2 的抢占级别高于 RTOS 阈值 5（数值更小），故 ISR 内禁止调用任何 RTOS API |
| DMA 通道优先级 | LOW | **HIGH** | LOW 在 LTDC 扫描 + LVGL 访问 SDRAM 时抢不到总线，DCMI 内部溢出丢点 |
| DMA FIFO | DISABLE | **ENABLE + Full 阈值 + 内存 INCR4** | SWD 对比：直接模式只有 2–6fps 且 `FEIF` 持续增长；FIFO Full + INCR4 两秒完成 696 个块，约 14.5fps。FCR 地址为 `0x4002643C`，不要误写 `M0AR(0x40026434)` |
| 传输长度 NDTR | 180000 字（整帧） | **7200 字（24 行）** | NDTR 为 16 位（≤65535），整帧会被静默截断；分块后中断约 375 次/秒（15fps） |
| DMA 模式 | CIRC/DBM | **NORMAL 逐块续排** | DBM+CIRC 在本板出现持续 FEIF、DCMI 溢出并冻结发布；NORMAL 历史日志可保持 `pub==vsync`、`eovr=0` |
| DCMI 中断 | 全关 | **仅开帧结束中断** | 用于帧计数与帧对齐校验；OVR/ERR 中断不可开（F4/F7 HAL 在溢出中断里会 Abort DMA）。ERRRI/OVRRI 改为任务侧读标志计数 |
| 画面通路 | LVGL 绘制到被扫描的帧缓冲 | **LTDC 第二图层硬件扫描独立帧缓冲** | 往正在扫描的缓冲写每帧变化的 663552 字节，会把“更新过程”显示出来（闪烁/撕裂） |

> 允许把已验证的 DCMI/DMA/GPIO 静态配置回填到 `.ioc`；NDTR、帧缓冲地址与首帧使能等运行时项仍保留在驱动内，回填后由 CubeMX 重新生成并复核。

### 3.3 分块 DMA 与帧同步

- 一帧 600 行 × 600 像素 × 2 字节 = 720000 字节；DCMI 每字给 2 个像素，故一行 = 300 个 32 位字。
- NDTR 只有 16 位，整帧 180000 字装不进去，所以一帧拆成 **25 块 × 24 行**（每块 7200 字，是 4 的整数倍，与 `MBURST_INC4` 对齐）。
- **块边界由 NORMAL TC 中断续排**：TC 后 DMA 硬件清除 EN，`cam_on_chunk_done()` 立即写入下一块 `M0AR/NDTR` 并重新置 EN；不关闭 DCMI，也不重新执行 `HAL_DCMI_Init()`。该做法来自历史实机日志，而不是通用 DMA 建议。
  - 本板反例：DBM+CIRC 在 NDTR 尚未耗尽时持续产生 FEIF，`pub` 冻结而 `eovr/desync` 增长。两种 FIFO 配置均复现，故不把 DBM 当作“零间隙”必然正确方案。
- **帧完成 = 第 25 块传完**（`CAM_CHUNKS_PER_FRAME = 25`），在同一块完成中断里发布 32 位原子包并切 `CFBAR`。
- **帧对齐**：置 `DCMI_CR_CAPTURE` 后 DCMI 从下一个 VSYNC 开始采集，块序号 0 的第一个字就是图像第 0 行第 0 个像素。帧结束中断只做帧计数与校验：帧内块计数应为 0（允许为 23，最后一块的 TC 可能压在 DMA FIFO 排空之后），其它值或出现 OVR/同步错误时置重排请求，任务侧带 1s 冷却时间重新排流。
- 帧结束回调必须先清 `DCMI_FLAG_FRAMERI` 再重开中断，否则会无限重入并占满 CPU。
- 发布采用 32 位原子包，中断只写一个对齐字，任务侧一次读取即得一致副本。

### 3.4 显示通路

- 第二个图层首帧写满后才打开，否则启动瞬间会看到自上而下逐行填图。
- **HAL 的 `HAL_LTDC_ConfigLayer()` 不会置 `LEN`**：配置完必须再调 `__HAL_LTDC_LAYER_ENABLE(&hltdc, LTDC_LAYER_2)` 并置 `LTDC_SRCR_VBR`，否则右栏永远是背景色（`ltdc.c` 初始化时显式清过 `LEN`，用来避免显示未初始化的帧缓冲）。
- 图层配置为窗口 x 424~1024 / y 0~600、RGB565、常量 alpha=255 不透明。600×2=1200B，满足 DMA 16B 对齐，但不再满足 64B 行宽对齐，需以实机 `fu/terr` 验证。
- **顶层混合因子必须为 `PAxCA`（配合 `Alpha0=0`）**：`CA` 模式下混合权重恒等于 CACR=255，窗口外（左栏 0~424）的黑色默认色会满权重盖住下层 LVGL 画面；`PAxCA` 下窗口外默认色 alpha=`Alpha0`=0 → 权重 0 透出下层，窗口内 RGB565 像素 alpha=0xFF → 不透明。`ltdc.c` 顶层配置与 `app_camera.c` 的 `cam_layer_config()` 两处必须保持一致。
- 换帧只改 `CFBAR` 并置 `LTDC_SRCR_VBR`，地址在垂直消隐期切换，扫描中途不变。
- **换帧必须在帧完成的同一时刻做（DMA 分块中断内）**，不能放到任务轮询里：相机一帧 66ms、面板一帧约 19ms，任务 40ms 的轮询延迟会让 DMA 回头覆盖正在被扫描的缓冲。
- **必须三缓冲**：双缓冲下发布新帧后 `CFBAR` 要等最多约 19ms 的垂直消隐才生效，而 DMA 立刻开始写"另一块"，那块正是 LTDC 此刻仍在扫描的旧帧 → 必现撕裂。三缓冲后写入目标按 0→1→2→0 轮换，任意时刻三者互不重叠。
- **LVGL 只渲染左栏 424×600**：424×2=848B；相机 600×2=1200B。两者满足 DMA 16B 对齐，但非 64B 行宽整数倍，实机验收必须检查 FIFO 下溢。
- **启动加载动画期间图层 0 会临时扩到 1024×600**（`lv_port_disp_set_area()`，详见《02.LVGL移植方案.md》§4.5）；此时相机图层尚未使能，仅当加载动画结束、图层 0 收回 424 宽后，右侧才开始出现相机画面。

SDRAM 地址分配（LVGL 帧缓冲由 02 分配，相机三块紧随其后，四块不得重叠）：

| 区域 | 起始地址 | 大小 | 用途 |
|------|----------|------|------|
| LVGL layer0 帧缓冲 | `0xC0000000` | 1024×600×2 = 1228800 B 预留 | 启动动画全屏；运行界面左侧 424×600 |
| 相机 FB0 | `0xC0140000` | 600×600×2 = 720000 B | DCMI DMA 直接写入目标 A |
| 相机 FB1 | `0xC0200000` | 600×600×2 = 720000 B | DCMI DMA 直接写入目标 B |
| 相机 FB2 | `0xC02C0000` | 600×600×2 = 720000 B | DCMI DMA 直接写入目标 C |

地址宏见 `App/camera/app_camera.h` 的 `CAM_FB0_ADDR` / `CAM_FB1_ADDR` / `CAM_FB2_ADDR` 与 `CAM_FB_NUM`；改动任一起点时必须同时核对四块缓冲不交叠。

### 3.5 帧率与统计

- 采集为连续模式，目标 600×600；界面只取最新完整帧，不追帧。
- 串口每 2s 打印 `fps | pub | vsync | desync | esync | eovr | dmaerr | fu | terr`。
- **以 `pub`（累计发布帧数）计算帧率**；DCMI 帧中断的 `vsync` 与按 25 块发布一帧的 `pub` 用于交叉校验（正常两者相等）。
- `desync` 是帧对齐校验失败/重排次数；`esync` / `eovr` 持续增长说明采样点丢失（通常为总线争用或 GPIO 速度不足），并会触发重排；`dmaerr` 为 DMA 传输错误累计。
- `fu` / `terr` 是 LTDC 的 **FIFO 下溢**与**取数传输错误**计数（F7 的 LTDC 只有一个 `FUIF`，不分图层），读 `LTDC->ISR` 后清 `LTDC->ICR`。`fu` 持续增长即为 SDRAM 带宽不足。
- 左侧授权界面通过 `AppCamera_GetStats()` 判断摄像头是否就绪，底栏每 500ms 刷新一次状态。

### 3.6 关键修正记录

| 问题 | 根因 / 修复 |
|------|-------------|
| 画面彩色条纹、只有部分区块显示、帧率虚高 | 整帧长度写入 16 位 NDTR 被截断。修复：改为每块 7200 字，并在块完成中断里预排下一块地址 |
| 画面逐块横向错位/斜纹、`pub` 与 `vsync` 对不上、画面缓慢滚动 | 需要区分“只重装 DMA 寄存器”和“停 DCMI 后整套重初始化”。当前按历史正常日志使用 NORMAL 逐块续排；DBM+CIRC 在本板会造成 `FEIF` 和采集中断 |
| 画面完全定格、CPU 占满 | 帧中断未先清 `FRAMERI` 就重开，导致无限重入。修复：回调首行清标志，再 `__HAL_DCMI_ENABLE_IT` |
| 相机区域闪烁/撕裂 | 每帧变化的像素写入 LTDC 正在扫描的缓冲。修复：改由第二个图层扫描独立帧缓冲 |
| 启动时画面逐行填入 | 图层在首帧未完成时就挂上未填满的缓冲。修复：首帧写满后才打开图层 |
| 其他任务长时间关中断导致每 5s 一条横带错位 | 若用 `__disable_irq()` 会屏蔽 DCMI/DMA 约 4ms，吞掉约 15 行；应改用 `taskENTER_CRITICAL()` 只屏蔽低优先级中断 |
| 左栏（图层窗口外区域）全黑、右栏正常 | 顶层混合因子用了 `CA`，权重恒=255，窗口外黑色默认色盖住下层。修复：改 `PAxCA` 且 `Alpha0=0`（只改 Alpha0 无效，CA 模式不读 Alpha0） |
| 输出尺寸不是 600×600、画面被拉伸 | OV2640 需先设置 `0x51/0x52/0x53/0x54/0x55/0x57` 图像窗口，再写 `0x5A/0x5B/0x5C` DSP 输出尺寸；检查 `OV2640_ImageWin_Set()` 与 `OV2640_OutSize_Set()` 的调用顺序 |
| 右栏始终是背景色、`pub` 不增长 | `HAL_LTDC_ConfigLayer()` 不置 `LEN`，图层从未使能。修复：配置后 `__HAL_LTDC_LAYER_ENABLE()` + `VBR` |
| `pub` 卡在 1、`dmaerr` 每 2s 稳定增长 | 传感器输出尺寸与 DMA 行字数不匹配 + `FIFO` 模式下错误会硬件关闭 DMA 流。修复：先修尺寸，再使用已验证的 FIFO Full + INCR4 |
| 右栏持续撕裂 | 双缓冲下发布后 `CFBAR` 要等垂直消隐生效，期间 DMA 写的另一块正是 LTDC 正在扫的旧帧。修复：改三缓冲 + 在 DMA 块完成中断里发布换帧 |
| 画面抖动/横带、`fu` 增长 | 两图层 + DMA 同时压 SDRAM 带宽。当前布局为 LVGL 424×600、相机 600×600，必须通过实机统计确认 848B/1200B 行宽可接受 |
| 左栏界面偶发缺块/错色 | 新增 DMA2D flush 路径后，LVGL 局部缓冲在内部 SRAM（可缓存），DMA2D 不维护 D-Cache。修复：flush 前 `SCB_CleanDCache_by_Addr()` + `__DSB()`（当前 Cache 未开启，属预防性修复） |

### 3.7 摄像头画面问题排查

先按《02.LVGL移植方案.md》§9 确认 LTDC 时序与 SDRAM/FMC 基础链路（纯色/棋盘格无花屏），再查摄像头专属问题：

| 现象 | 优先检查 |
|------|----------|
| 彩色条纹、只有部分区块显示、帧率虚高 | DMA NDTR 是否为 24 行共 7200 字；TC 中断是否续排下一块；`pub` 是否持续增长 |
| 画面逐块横向错位、缓慢滚动 | 检查块完成中断是否及时续排；当前不要切回本板会停流的 DBM+CIRC |
| 画面完全定格、CPU 占满 | 帧中断是否先清 `DCMI_FLAG_FRAMERI` 再重开 |
| 每 5s 一条横带错位 | 是否有任务用 `__disable_irq()` 长时间屏蔽 DCMI/DMA；应使用 `taskENTER_CRITICAL()` |
| 右栏闪烁/撕裂 | 是否三缓冲（`CAM_FB_NUM=3`）；换帧是否在 DMA 块完成中断内完成而不是任务轮询；是否往 LTDC 正在扫描的缓冲写像素 |
| 画面整体抖动/横带、`fu` 增长 | LVGL 是否仍按 1024 宽渲染；图层 0 是否为 424 宽；相机是否为 600 宽；FIFO 下溢是否持续增长 |
| 启动瞬间逐行填图 | 图层是否在首帧写满前就打开 |
| 右侧位置/尺寸不对 | 图层窗口是否为 x 424~1024 / y 0~600，`WindowX1/WindowY1` 为右开区间 |
| 左栏全黑、右栏画面正常 | 顶层混合因子是否为 `CA`；必须为 `PAxCA` + `Alpha0=0`，且 `ltdc.c` 与 `cam_layer_config()` 两处一致 |
| `desync` 持续增长 | 采集流反复错位：先看 `eovr/esync` 是否同时增长（总线带宽/GPIO 速度），再看是否有任务长时间关中断 |
| 相机区域采样点丢失（`eovr/esync` 增长） | DCMI GPIO 是否为 PULLUP + Very High；DMA 是否 HIGH；`fe` 是否增长；与 LTDC/DMA2D 的 SDRAM 带宽争用 |

### 3.8 与其他任务的临界区约束

- 任何任务都不得用 `__disable_irq()` 长时间屏蔽中断；应使用 `taskENTER_CRITICAL()`（BASEPRI=5），屏蔽所有优先级数值 ≥5 的中断。当前工程为 SysTick/TIM7，DCMI/DMA2_Stream1（优先级 2）不受影响。
- 若用 `__disable_irq()` 屏蔽 DCMI/DMA 约 4ms，会吞掉约 15 行，表现为相机区域每 5s 出现一条横带错位。
- 各任务共享 SDRAM 带宽：若 `eovr/esync` 增长，先核对 DCMI GPIO 速度、DMA 优先级与 FIFO，再考虑降低其他总线主设备的占用。

## 6. 2026-11-18 实机调试结论（重要，先读这里）

本轮通过串口 + ST-Link（SWD 直接读 RAM/寄存器）逐项排查，结论与遗留问题如下。

### 6.1 已定位并修复的软件缺陷

| 现象 | 根因 | 修复 |
|------|------|------|
| `[cam] dma start failed`，相机完全不启动 | `HAL_DMA_Init()` 的 `DMA_CheckFifoParam()` 对 32 位（WORD）数据流只允许 `FIFO=FULL + INCR4`；原配置 `HALFFULL + INC4` 直接返回 `HAL_ERROR` | `MemBurst = DMA_MBURST_SINGLE` |
| 接上 SWD 调试器后整机卡死、`uwTick` 不增长 | `Camera_DelayUs()` 依赖 DWT CYCCNT，调试器可清掉 `CYCCNTENA`，`while(CYCCNT-start<ticks)` 永久死等 | 先检测两次读取是否递增，不递增则退回定长空循环 |
| 每 32 位 DR 中四个字节完全相同 | `HSPolarity = HIGH` 在错误相位采样 | `HSPolarity = LOW`：SWD 读取 DR 从 `BBBBBBBB` 变为 `AD36AD36`，帧缓冲 `low==high` 从 100% 降至约 3% |
| 帧缓冲每 32 位字是 4 个相同字节 | 见 §6.3（未解决） | — |
| 屏幕刷新率只有 52.7Hz，画面"不完全正确" | 像素时钟按 45MHz 配置，而 ATK-7016 手册/正点原子 `ATK7016_mode` 为 **51.2MHz / 60Hz** | `PLLSAIN=307, PLLSAIR=3, PLLSAIDIVR=2` → 51.17MHz |
| 相机输出几何不确定 | DSP image size 回读只有 800×600，原 1152×1152 窗口超出 DSP 能力 | 当前改为 **居中裁 600×600、1:1 直出（不缩放）**，偏移 (500, 300) |
| `0xDA` 取值 | 正点原子 OV2640 RGB565 序列使用 `0x09`（RGB565 + 低字节先出）；`0x08` 是高字节先出 | 改为 `0x09`，与 STM32 DCMI 8 位模式下首字节进入 `DCMI_DR` LSB 的打包方式一致；待最新固件复验颜色 |
| DCMI 数据每 32 位只有同一个字节重复 | HSYNC 极性错误导致采样相位不正确 | SWD 实测 `HIGH` 时 DR=`BBBBBBBB`；`LOW` 时 DR=`AD36AD36`，每行 DMA 字数恢复为 288，故改回 `HSPolarity=LOW` |

### 6.2 已量到的硬指标（SWD 读 RAM，串口掉线时也可复现）

- `s_linesPerFrame = 576`：DCMI 行中断统计的一帧行数正确。
- `g_dataDuty[8] = 83/17/95/72/85/68/63/22 %`：8 根数据线都在被驱动，**接线不是断路**。
- `PH8` 高电平占 27%（行同步存在）；`PB7` 高电平约 95%（帧同步为低脉冲）。
- `g_wordsPerLineMax = 1712`：流正常时两次行中断之间 DMA 前进了 1712 字，而 576 像素/行应为 288 字 → **DCMI 大约每 6 行才识别到一次行同步**。
- 帧缓冲统计：`low==high` 占 99.8%，整帧只有 32~480 种取值，逐行近似常数。

### 6.3 尚未解决的根因与硬件核对项

上述旧数据组合（同步信号有、数据线在动、但采到的是"静态字节"且行同步只认到 1/6）曾指向
DCMI 采样时序或数据打包问题。当前已依据正点原子参考代码修正 `0xDA=0x09`，并恢复历史可工作的
NORMAL 分块续排；下一步必须用最新固件重新读取显存，确认 `low==high` 比例是否消失，不能继续用旧转储下结论。

请用示波器/逻辑分析仪按下面顺序核对（每项都直接决定能否出图）：

1. **PA6 是否真的是 OV2640 的 PCLK**？现场观察 PCLK 上升沿是否落在数据稳定区（数据应在
   PCLK 的某个边沿前后稳定 ≥10ns）。若 PA6 接的是 XCLK/其他时钟，则 PCLK 根本没进 MCU。
2. **模块 XCLK 接哪里**？本工程未驱动 PA8。若模组无 24MHz 晶振，XCLK 悬空时传感器内部时序
   会异常（同步信号可能仍存在，但像素输出不可靠）。需要时可把 PA8 配成 MCO1 输出 25MHz 验证。
3. **D0~D7 与 PCLK 是否同源同相**：确认 D0~D7 接的确实是模块的数据脚，并检查是否有
   74HC245 之类的缓冲器造成额外延迟/反向。
4. HREF(PH8)/VSYNC(PB7) 与模块对应脚的通断（本工程实测这两根有信号，优先查 PCLK 与数据）。
