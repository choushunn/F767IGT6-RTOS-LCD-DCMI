# DCMI 摄像头模块方案（OV5640 / 按行 DMA / LTDC 第二图层）

> **前提**：FreeRTOS 任务框架、UART 打印接口（`AppUart_Printf`）、LVGL 显示与基础测试界面已验收（见《01.FreeRTOS移植方案.md》《02.LVGL移植方案.md》）。
> 本文是 LVGL 基础界面验收后的下一步，只覆盖 DCMI 摄像头采集与显示；触摸与输入见《03.触摸移植方案.md》。
> 引脚分配见《实验46 照相机实验_引脚配置分析.md》。

## 1. 概述

| 项目 | 说明 |
|------|------|
| 传感器 | OV5640（SCCB 配置，模组自带 24MHz 晶振） |
| 输出 | 480×480，RGB565（460800 字节/帧），实测 15fps |
| 采集接口 | DCMI 8 位并口，硬件同步，上升沿采样 |
| 传输 | DMA2_Stream1，按行双缓冲（NDTR=240 字/行），CIRCULAR + FIFO 半满 |
| 帧缓冲 | 外部 SDRAM **三块**：`0xC0140000`（FB0）、`0xC01C0000`（FB1）、`0xC0240000`（FB2） |
| 显示 | LTDC 第二个图层（HAL 常量 `LTDC_LAYER_2`，配置索引 1），窗口 x 544~1024 / y 60~540 |
| LVGL 区域 | 图层 0 只覆盖左栏 0~544，LVGL 分辨率 544×600（652800 B） |
| 刷新节奏 | 换帧在 DMA 行中断内完成（帧满 480 行即切 CFBAR）；LVGL 定时器 40ms 只做统计与首帧使能 |

代码位置：`App/camera/`（`app_camera` 采集与显示、`ov5640` 传感器、`sccb` 控制总线、`pcf8574` 扩展 IO、`camera_util` 微秒延时）。

## 2. 数据通路

- **采集**：OV5640 →（DCMI 8 位并口）→ DMA2_Stream1（`NDTR = 一行 240 个 32 位字`，CIRCULAR + 行双缓冲）→ 行完成中断把该行拷入 SDRAM 当前帧缓冲 → 行号累计到 480 即发布一帧（32 位原子包：bit[1:0] 为缓冲序号 0~2，高位为帧序号）。
- **显示**：最新完整帧 → LTDC 第二个图层硬件扫描；**发布与换帧都在 DMA 行中断内完成**（只改 `CFBAR` 并置 `LTDC_SRCR_VBR`），垂直消隐期生效。LVGL 不搬运、不绘制任何相机像素。
- **三缓冲**：写入目标按 0→1→2→0 轮换，保证 DMA 写入的缓冲既不是刚发布的那块，也不是 LTDC 正在扫描的那块（双缓冲必现撕裂，见 §3.6）。
- **边界**：本文只覆盖相机采集与显示；其他任务与本模块共享任务调度与 SDRAM 总线，临界区约束见 §3.8。

## 3. 摄像头

### 3.1 上电、复位与控制

| 信号 | 引脚 | 说明 |
|------|------|------|
| PWDN | PCF8574 P2（软件 I2C：SCL=PH4 / SDA=PH5，7 位地址 0x20） | 低电平上电；先保持高电平掉电，再清零 |
| RESET | PA15 | 低电平复位，释放后延时再访问 SCCB |
| SCCB SCL / SDA | PB4 / PB3 | 软件时序；SCL 推挽输出、SDA 开漏输出（可读回电平） |
| XCLK | PA8 | **不使用**（模组自带晶振；`gpio.c` 仍把它配成输出并驱低，属未使用引脚） |
| 蜂鸣器 BEEP | PCF8574 P0（与 PWDN 同一颗扩展 IO） | 低电平驱动响；`PCF8574_WriteBit()` 是读-改-写，写 P0 不会改变 P2 的 PWDN 电平 |

> PA15 / PB3 / PB4 是 JTAG 专用引脚，本工程使用 SWD 调试，可安全复用；若改为 JTAG 调试会产生冲突。

初始化顺序：PCF8574 配置并使 PWDN 保持高电平（掉电）→ OV5640 RST 拉低 20ms → PWDN 清零上电 → 5ms → RST 释放 → 20ms → SCCB 引脚初始化 → 读 ID 校验（0x5640）→ RGB565 模式 → **`OV5640_SetMirrorFlip(CAM_MIRROR_H, CAM_FLIP_V)`** → **直接写 `0x3808~0x380B` 设 480×480**（偏移 16/4）→ 回读 `0x3808~0x380F` 打印输出宽高、HTS、VTS → DCMI 重配 → 启动 DMA → 置 `DCMI_CR_CAPTURE`。

> **画面方向**：默认配置表里 `0x3821=0x00`（未开水平镜像）、`0x3820=0x46`（开了垂直翻转），与本板模组装配方向相反，实测预览左右反。`OV5640_SetMirrorFlip()` 通过 `0x3821`/`0x3820` 的 bit[2:1] 打开水平镜像，开关集中在 `app_camera.h` 的 `CAM_MIRROR_H` / `CAM_FLIP_V`；改后串口打印 `[cam] mirror=.. flip=.. reg3820=.. reg3821=..` 便于核对。

> ⚠ 设置输出尺寸**不能**沿用参考例程里 `0x3212` 组 3 包裹的写法：该方式要等下一帧才生效，紧随其后的回读仍是旧值，本板 DVP RGB565 实测完全没生效（回读仍是 1280×720），导致 DMA 行字数与真实行宽错位。

### 3.2 DCMI / DMA 配置

| 项目 | 默认/基线 | 驱动实际 | 原因 |
|------|---------------|----------------|------|
| PCKPolarity | FALLING | **RISING** | 与模组实测及参考例程一致；FALLING 会在错误的边沿采样 |
| DCMI 数据/同步 GPIO | NOPULL + Low speed | **PULLUP + Very High** | Low speed 无法满足 PCLK 频率 |
| DMA2_Stream1 中断优先级 | 0 | **2** | 0 会强烈抢占 SysTick/TIM7 时基；2 的抢占级别高于 RTOS 阈值 5（数值更小），故 ISR 内禁止调用任何 RTOS API |
| DMA 通道优先级 | LOW | **HIGH** | LOW 在 LTDC 扫描 + LVGL 访问 SDRAM 时抢不到总线，DCMI 内部溢出丢点 |
| DMA FIFO | DISABLE | **ENABLE（1/2 阈值）** | 吸收总线抖动，避免丢采样点 |
| 传输长度 NDTR | 115200 字（整帧） | **240 字（一行）** | NDTR 为 16 位（≤65535），整帧 115200 会被静默截断成 49664；`USE_FULL_ASSERT` 未开时断言也不触发，导致缓冲边界与真实帧边界永久错位 |
| DCMI 中断 | 全关 | **仅开帧结束中断** | 用于帧计数；OVR/ERR 中断不可开（F4 HAL 在溢出中断里会 Abort DMA）。ERRRI/OVRRI 改为任务侧读标志计数 |
| 画面通路 | LVGL 绘制到被扫描的帧缓冲 | **LTDC 第二图层硬件扫描独立帧缓冲** | 往正在扫描的缓冲写每帧变化的 460800 字节，会把“更新过程”显示出来（闪烁/撕裂） |

> 允许把已验证的 DCMI/DMA/GPIO 静态配置回填到 `.ioc`；NDTR、帧缓冲地址与首帧使能等运行时项仍保留在驱动内，回填后由 CubeMX 重新生成并复核。

### 3.3 按行 DMA 与帧同步

- 一帧 480 行 × 480 像素 × 2 字节 = 460800 字节；DCMI 每字给 2 个像素，故一行 = 240 个 32 位字，正好是 `NDTR` 的取值。
- 双缓冲的“两个缓冲”是**两行行缓冲**，不是两帧；CIRCULAR 让 DMA 在行与行之间不停顿。
- 帧完成由“行号累计到 480”判定，不依赖帧中断；DCMI 帧中断只做真实帧计数。
- 帧结束回调必须先清 `DCMI_FLAG_FRAMERI` 再重开中断，否则会无限重入并占满 CPU。
- 发布采用 32 位原子包，中断只写一个对齐字，任务侧一次读取即得一致副本。

### 3.4 显示通路

- 第二个图层首帧写满后才打开，否则启动瞬间会看到自上而下逐行填图。
- **HAL 的 `HAL_LTDC_ConfigLayer()` 不会置 `LEN`**：配置完必须再调 `__HAL_LTDC_LAYER_ENABLE(&hltdc, LTDC_LAYER_2)` 并置 `LTDC_SRCR_VBR`，否则右栏永远是背景色（`ltdc.c` 初始化时显式清过 `LEN`，用来避免显示未初始化的帧缓冲）。
- 图层配置为窗口 x 544~1024 / y 60~540、RGB565、常量 alpha=255 不透明。
- **顶层混合因子必须为 `PAxCA`（配合 `Alpha0=0`）**：`CA` 模式下混合权重恒等于 CACR=255，窗口外（左栏 0~544）的黑色默认色会满权重盖住下层 LVGL 画面（实测左栏全黑）；`PAxCA` 下窗口外默认色 alpha=`Alpha0`=0 → 权重 0 透出下层，窗口内 RGB565 像素 alpha=0xFF → 不透明。`ltdc.c` 顶层配置与 `cam_display_show()` 两处必须保持一致。
- 换帧只改 `CFBAR` 并置 `LTDC_SRCR_VBR`，地址在垂直消隐期切换，扫描中途不变。
- **换帧必须在帧完成的同一时刻做（DMA 行中断内）**，不能放到任务轮询里：相机一帧 66ms、面板一帧约 19ms，任务 40ms 的轮询延迟会让 DMA 回头覆盖正在被扫描的缓冲。
- **必须三缓冲**：双缓冲下发布新帧后 `CFBAR` 要等最多约 19ms 的垂直消隐才生效，而 DMA 立刻开始写"另一块"，那块正是 LTDC 此刻仍在扫描的旧帧 → 必现撕裂。三缓冲后写入目标按 0→1→2→0 轮换，任意时刻三者互不重叠。
- **LVGL 只渲染左栏 544×600**：两个图层都从同一片 SDRAM 连续扫描；若 LVGL 按完整 1024 宽输出，会把图层 0 读取带宽提高到约 69MB/s，再叠加相机层与 DMA 写入后接近 FMC SDRAM 实际上限，容易出现 LTDC FIFO 下溢（画面抖动）。裁到 544 宽后降到约 35MB/s。
- **启动加载动画期间图层 0 会临时扩到 1024×600**（`lv_port_disp_set_area()`，详见《02.LVGL移植方案.md》§4.5）；此时相机图层尚未使能，仅当加载动画结束、图层 0 收回 544 宽后，右侧才开始出现相机画面。

SDRAM 地址分配（LVGL 帧缓冲由 02 分配，相机三块紧随其后，四块不得重叠）：

| 区域 | 起始地址 | 大小 | 用途 |
|------|----------|------|------|
| LVGL layer0 帧缓冲 | `0xC0000000` | 1024×600×2 = 1228800 B 预留 | 启动动画全屏；运行界面左侧 544×600 |
| 相机 FB0 | `0xC0140000` | 480×480×2 = 460800 B | DCMI DMA 行拷贝目标 A |
| 相机 FB1 | `0xC01C0000` | 480×480×2 = 460800 B | DCMI DMA 行拷贝目标 B |
| 相机 FB2 | `0xC0240000` | 480×480×2 = 460800 B | DCMI DMA 行拷贝目标 C |

地址宏见 `App/camera/app_camera.h` 的 `CAM_FB0_ADDR` / `CAM_FB1_ADDR` / `CAM_FB2_ADDR` 与 `CAM_FB_NUM`；改动任一起点时必须同时核对四块缓冲不交叠。

### 3.5 帧率与统计

- 采集为连续模式，实测 480×480@15fps；界面只取最新完整帧，不追帧。
- 串口每 2s 打印 `fps | pub | vsync | esync | eovr | dmaerr | fu | terr`。
- **以 `pub`（累计发布帧数）计算帧率**；本板实测 `pub == vsync`（DCMI 帧中断与 480 行发布严格一一对应），可作为交叉校验。
- `esync` / `eovr` 持续增长说明采样点丢失（通常为总线争用或 GPIO 速度不足）；`dmaerr` 为 DMA 传输错误累计。
- `fu` / `terr` 是 LTDC 的 **FIFO 下溢**与**取数传输错误**计数（F7 的 LTDC 只有一个 `FUIF`，不分图层），读 `LTDC->ISR` 后清 `LTDC->ICR`。`fu` 持续增长即为 SDRAM 带宽不足。
- 左侧状态面板通过 `AppCamera_GetStats()` 读取同一批计数，0.5s 滑窗算 fps，500ms 刷新一次。

### 3.6 关键修正记录

| 问题 | 根因 / 修复 |
|------|-------------|
| 画面彩色条纹、只有部分区块显示、帧率虚高 | 整帧长度写入 16 位 NDTR 被截断。修复：改为一行 240 字，CIRCULAR + 行双缓冲 |
| 画面完全定格、CPU 占满 | 帧中断未先清 `FRAMERI` 就重开，导致无限重入。修复：回调首行清标志，再 `__HAL_DCMI_ENABLE_IT` |
| 相机区域闪烁/撕裂 | 每帧变化的像素写入 LTDC 正在扫描的缓冲。修复：改由第二个图层扫描独立帧缓冲 |
| 启动时画面逐行填入 | 图层在首帧未完成时就挂上未填满的缓冲。修复：首帧写满后才打开图层 |
| 其他任务长时间关中断导致每 5s 一条横带错位 | 若用 `__disable_irq()` 会屏蔽 DCMI/DMA 约 4ms，吞掉约 15 行；应改用 `taskENTER_CRITICAL()` 只屏蔽低优先级中断 |
| 左栏（图层窗口外区域）全黑、右栏正常 | 顶层混合因子用了 `CA`，权重恒=255，窗口外黑色默认色盖住下层。修复：改 `PAxCA` 且 `Alpha0=0`（只改 Alpha0 无效，CA 模式不读 Alpha0） |
| 传感器回读仍是 1280×720、画面只有部分区块 | `OV5640_OutSize_Set` 用 `0x3212` 组 3 包裹，本板 DVP RGB565 下不生效。修复：直接写 `0x3808~0x380B` 与偏移寄存器 |
| 右栏始终是背景色、`pub` 不增长 | `HAL_LTDC_ConfigLayer()` 不置 `LEN`，图层从未使能。修复：配置后 `__HAL_LTDC_LAYER_ENABLE()` + `VBR` |
| `pub` 卡在 1、`dmaerr` 每 2s 稳定增长 | 传感器输出尺寸与 DMA 行字数不匹配 + `FIFO` 模式下错误会硬件关闭 DMA 流。修复：先修尺寸；FIFO 保持半满（一行 240 字是 8 的整数倍，不会触发 FE） |
| 右栏持续撕裂 | 双缓冲下发布后 `CFBAR` 要等垂直消隐生效，期间 DMA 写的另一块正是 LTDC 正在扫的旧帧。修复：改三缓冲 + 在 DMA 行中断里发布换帧 |
| 画面抖动/横带、`fu` 增长 | 两图层 + DMA 同时压 SDRAM 带宽。修复：LVGL 分辨率限制为 544×600、图层 0 窗口裁到 0~544 |

### 3.7 摄像头画面问题排查

先按《02.LVGL移植方案.md》§9 确认 LTDC 时序与 SDRAM/FMC 基础链路（纯色/棋盘格无花屏），再查摄像头专属问题：

| 现象 | 优先检查 |
|------|----------|
| 彩色条纹、只有部分区块显示、帧率虚高 | DMA NDTR 是否仍为整帧长度（必须是一行 240 字）；DMA 是否 CIRCULAR + 行双缓冲 |
| 画面完全定格、CPU 占满 | 帧中断是否先清 `DCMI_FLAG_FRAMERI` 再重开 |
| 每 5s 一条横带错位 | 是否有任务用 `__disable_irq()` 长时间屏蔽 DCMI/DMA；应使用 `taskENTER_CRITICAL()` |
| 右栏闪烁/撕裂 | 是否三缓冲（`CAM_FB_NUM=3`）；换帧是否在 DMA 行中断内完成而不是任务轮询；是否往 LTDC 正在扫描的缓冲写像素 |
| 画面整体抖动/横带、`fu` 增长 | LVGL 是否仍按 1024 宽渲染；图层 0 窗口是否裁到 0~544；相机 DMA 是否与 LTDC 争 SDRAM 带宽 |
| 启动瞬间逐行填图 | 图层是否在首帧写满前就打开 |
| 右侧位置/尺寸不对 | 图层窗口是否为 x 544~1024 / y 60~540，`WindowX1/WindowY1` 为右开区间 |
| 左栏全黑、右栏画面正常 | 顶层混合因子是否为 `CA`；必须为 `PAxCA` + `Alpha0=0`，且 `ltdc.c` 与 `cam_display_show()` 两处一致 |
| 相机区域采样点丢失（`eovr/esync` 增长） | DCMI GPIO 是否为 PULLUP + Very High；DMA 是否 HIGH + FIFO 1/2；与 LTDC/DMA2D 的 SDRAM 带宽争用 |

### 3.8 与其他任务的临界区约束

- 任何任务都不得用 `__disable_irq()` 长时间屏蔽中断；应使用 `taskENTER_CRITICAL()`（BASEPRI=5），屏蔽所有优先级数值 ≥5 的中断。当前工程为 SysTick/TIM7，DCMI/DMA2_Stream1（优先级 2）不受影响。
- 若用 `__disable_irq()` 屏蔽 DCMI/DMA 约 4ms，会吞掉约 15 行，表现为相机区域每 5s 出现一条横带错位。
- 各任务共享 SDRAM 带宽：若 `eovr/esync` 增长，先核对 DCMI GPIO 速度、DMA 优先级与 FIFO，再考虑降低其他总线主设备的占用。

## 4. 验证

先确认《02.LVGL移植方案.md》§6 的基础界面验收通过，再接摄像头：

1. 串口出现 `[cam] ov5640 id ok`、`[cam] mirror=1 flip=1 reg3820=0x46 reg3821=0x06`、`[cam] sensor out=480x480 hts=... vts=...`、`[cam] capture started`、`[cam] init done`。
2. 右栏画面连续、无撕裂/横带；首帧后图层才打开，无逐行填图过程。
3. 每 2s 统计中 `fps` 稳定在 15 左右，`pub == vsync` 且持续增长，`esync/eovr/dmaerr/fu/terr` 全部不增长。
4. 左栏为 544 宽状态面板（运行时间、相机 FPS/帧数/错误、堆、触摸、LED），触摸可切换 LED1。
5. 触摸、LED、摄像头与 LVGL 同时运行时无卡死、无花屏。

## 5. 不做的事

- 不做 JPEG 输出、软件旋转、录像与存储；画面方向用传感器内置镜像/翻转寄存器纠正（`CAM_MIRROR_H` / `CAM_FLIP_V`）。
- 不接入 DMA2D 做相机画面搬运（当前由硬件图层直接扫描）。
- 不做多分辨率动态切换；480×480 与 `CAM_IMG_W/H`、DMA 行字数、图层窗口三者绑定，改动需同步。
