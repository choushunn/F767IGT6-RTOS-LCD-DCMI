# DCMI 摄像头模块方案（OV5640 / 按行 DMA / LTDC 第二图层）

> **前提**：FreeRTOS 任务框架、UART 打印接口（`AppUart_Printf`）、LVGL 显示与基础测试界面已验收（见《01.FreeRTOS移植方案.md》《02.LVGL移植方案.md》）。
> 本文是 LVGL 基础界面验收后的下一步，只覆盖 DCMI 摄像头采集与显示；触摸与输入见《03.触摸移植方案.md》。
> 引脚分配见《00.F429IGT6实验箱引脚说明.md》。

## 1. 概述

| 项目 | 说明 |
|------|------|
| 传感器 | OV5640（SCCB 配置，模组自带 24MHz 晶振） |
| 输出 | 480×480，RGB565（460800 字节/帧） |
| 采集接口 | DCMI 8 位并口，硬件同步，上升沿采样 |
| 传输 | DMA2_Stream1，按行双缓冲，CIRCULAR |
| 帧缓冲 | 外部 SDRAM `0xC0100000`（FB0）、`0xC0180000`（FB1） |
| 显示 | LTDC 第二个图层（HAL 常量 `LTDC_LAYER_2`，配置索引 1），窗口 x 320~800 / y 0~480 |
| 刷新节奏 | LVGL 定时器按 `APP_CAMERA_REFRESH_MS`（40ms）调用 `AppCamera_PollFrame()` |

代码位置：`App/camera/`（`app_camera` 采集与显示、`ov5640` 传感器、`sccb` 控制总线、`pca9555` 扩展 IO、`camera_util` 微秒延时）。

## 2. 数据通路

- **采集**：OV5640 →（DCMI 8 位并口）→ DMA2_Stream1（`NDTR = 一行 240 个 32 位字`，CIRCULAR + 双缓冲）→ 行完成中断把该行拷入 SDRAM 帧缓冲 → 行号累计到 480 即发布一帧（32 位原子包：低 1 位为缓冲序号，高位为帧序号）。
- **显示**：最新完整帧 → LTDC 第二个图层硬件扫描（只改 `CFBAR` 并置 `LTDC_SRCR_VBR`，垂直消隐期生效）→ 屏幕右栏。LVGL 不搬运、不绘制任何相机像素。
- **边界**：本文只覆盖相机采集与显示；其他任务与本模块共享任务调度与 SDRAM 总线，临界区约束见 §3.8。

## 3. 摄像头

### 3.1 上电、复位与控制

| 信号 | 引脚 | 说明 |
|------|------|------|
| PWDN | PCA9555 P0.2（I2C2，0x20） | 低电平上电；先保持高电平掉电，再清零 |
| RESET | PA15 | 低电平复位，释放后延时再访问 SCCB |
| SCCB SCL / SDA | PB4 / PB3 | 软件时序；SCL 推挽输出、SDA 开漏输出（可读回电平） |
| XCLK | PA8 | **不使用**（模组自带晶振；`gpio.c` 仍把它配成输出并驱低，属未使用引脚） |

> PA15 / PB3 / PB4 是 JTAG 专用引脚，本工程使用 SWD 调试，可安全复用；若改为 JTAG 调试会产生冲突。

初始化顺序：PCA9555 配置并使 PWDN 保持高电平（掉电）→ OV5640 RST 拉低 20ms → PWDN 清零上电 → 5ms → RST 释放 → 20ms → SCCB 引脚初始化 → 读 ID 校验 → RGB565 模式与图像参数 → DCMI 重配 → 设置输出尺寸并回读 `0x3808~0x380F`（输出宽高、HTS、VTS）→ 启动 DMA → 置 `DCMI_CR_CAPTURE`。

### 3.2 DCMI / DMA 配置

| 项目 | 默认/基线 | 驱动实际 | 原因 |
|------|---------------|----------------|------|
| PCKPolarity | FALLING | **RISING** | 与模组实测及参考例程一致；FALLING 会在错误的边沿采样 |
| DCMI 数据/同步 GPIO | NOPULL + Low speed | **PULLUP + Very High** | Low speed 无法满足 PCLK 频率 |
| DMA2_Stream1 中断优先级 | 0 | **2** | 0 会强烈抢占 SysTick/TIM7 时基；2 的抢占级别高于 RTOS 阈值 5（数值更小），故 ISR 内禁止调用任何 RTOS API |
| DMA 通道优先级 | LOW | **HIGH** | LOW 在 LTDC 扫描 + LVGL 访问 SDRAM 时抢不到总线，DCMI 内部溢出丢点 |
| DMA FIFO | DISABLE | **ENABLE（1/2 阈值）** | 吸收总线抖动，避免丢采样点 |
| 传输长度 NDTR | 115200 字（整帧） | **240 字（一行）** | NDTR 为 16 位（≤65535），整帧 115200 会被静默截断成 49664；`USE_FULL_ASSERT` 未开时断言也不触发，导致缓冲边界与真实帧边界永久错位 |
| DCMI 中断 | 全关 | **仅开帧结束中断** | 用于帧计数；OVR/ERR 中断不可开（F4 HAL 在溢出中断里会 Abort DMA）。ERRRI/OVRRI 改为任务侧读标志计数 |
| 画面通路 | LVGL 绘制到被扫描的帧缓冲 | **LTDC 第二图层硬件扫描独立帧缓冲** | 往正在扫描的缓冲写每帧变化的 460800 字节，会把“更新过程”显示出来（闪烁/撕裂） |

> 允许把已验证的 DCMI/DMA/GPIO 静态配置回填到 `.ioc`；NDTR、帧缓冲地址与首帧使能等运行时项仍保留在驱动内，回填后由 CubeMX 重新生成并复核。

### 3.3 按行 DMA 与帧同步

- 一帧 480 行 × 480 像素 × 2 字节 = 460800 字节；DCMI 每字给 2 个像素，故一行 = 240 个 32 位字，正好是 `NDTR` 的取值。
- 双缓冲的“两个缓冲”是**两行行缓冲**，不是两帧；CIRCULAR 让 DMA 在行与行之间不停顿。
- 帧完成由“行号累计到 480”判定，不依赖帧中断；DCMI 帧中断只做真实帧计数。
- 帧结束回调必须先清 `DCMI_FLAG_FRAMERI` 再重开中断，否则会无限重入并占满 CPU。
- 发布采用 32 位原子包，中断只写一个对齐字，任务侧一次读取即得一致副本。

### 3.4 显示通路

- 第二个图层首帧写满后才打开，否则启动瞬间会看到自上而下逐行填图。
- 图层配置为窗口 x 320~800 / y 0~480、RGB565、常量 alpha=255 不透明。
- **顶层混合因子必须为 `PAxCA`（配合 `Alpha0=0`）**：`CA` 模式下混合权重恒等于 CACR=255，窗口外（左栏 0~320）的黑色默认色会满权重盖住下层 LVGL 画面（实测左栏全黑）；`PAxCA` 下窗口外默认色 alpha=`Alpha0`=0 → 权重 0 透出下层，窗口内 RGB565 像素 alpha=0xFF → 不透明。`ltdc.c` 顶层配置与 `cam_display_show()` 两处必须保持一致。
- 换帧只改 `CFBAR` 并置 `LTDC_SRCR_VBR`，地址在垂直消隐期切换，扫描中途不变。
- SDRAM 地址分配：LVGL 基础界面占用 `0xC0000000` 起的 768000 B（由 02 分配），摄像头在其后新增两块缓冲，三块不得重叠。

| 区域 | 起始地址 | 大小 | 用途 |
|------|----------|------|------|
| LVGL layer0 帧缓冲 | `0xC0000000` | 800×480×2 = 768000 B（`0xBB800`） | 基础界面（见 02） |
| 相机 FB0 | `0xC0100000` | 480×480×2 = 460800 B（`0x70800`） | DCMI DMA 行拷贝目标 A |
| 相机 FB1 | `0xC0180000` | 480×480×2 = 460800 B | DCMI DMA 行拷贝目标 B |

地址宏见 `App/camera/app_camera.c` 的 `CAM_FB0_ADDR` / `CAM_FB1_ADDR`；改动任一起点时必须同时核对三块缓冲不交叠。

### 3.5 帧率与统计

- 界面轮询周期为 `APP_CAMERA_REFRESH_MS = 40ms`（目标 25fps），实际采集帧率由传感器配置决定，界面只取最新完整帧，不追帧。
- 串口每 2s 打印 `fps | pub | vsync | esync | eovr | dmaerr`。
- **以 `pub`（累计发布帧数）计算帧率**：实测 DCMI 帧中断回调存在竞态漏计，`vsync` 约为 `pub` 的 1/4，不能作为帧率依据。
- `esync` / `eovr` 持续增长说明采样点丢失（通常为总线争用或 GPIO 速度不足）；`dmaerr` 为 DMA 传输错误累计。

### 3.6 关键修正记录

| 问题 | 根因 / 修复 |
|------|-------------|
| 画面彩色条纹、只有部分区块显示、帧率虚高 | 整帧长度写入 16 位 NDTR 被截断。修复：改为一行 240 字，CIRCULAR + 行双缓冲 |
| 画面完全定格、CPU 占满 | 帧中断未先清 `FRAMERI` 就重开，导致无限重入。修复：回调首行清标志，再 `__HAL_DCMI_ENABLE_IT` |
| 相机区域闪烁/撕裂 | 每帧变化的像素写入 LTDC 正在扫描的缓冲。修复：改由第二个图层扫描独立帧缓冲 |
| 启动时画面逐行填入 | 图层在首帧未完成时就挂上未填满的缓冲。修复：首帧写满后才打开图层 |
| 其他任务长时间关中断导致每 5s 一条横带错位 | 若用 `__disable_irq()` 会屏蔽 DCMI/DMA 约 4ms，吞掉约 15 行；应改用 `taskENTER_CRITICAL()` 只屏蔽低优先级中断 |
| 左栏（图层窗口外区域）全黑、右栏正常 | 顶层混合因子用了 `CA`，权重恒=255，窗口外黑色默认色盖住下层。修复：改 `PAxCA` 且 `Alpha0=0`（只改 Alpha0 无效，CA 模式不读 Alpha0） |

### 3.7 摄像头画面问题排查

先按《02.LVGL移植方案.md》§9 确认 LTDC 时序与 SDRAM/FMC 基础链路（纯色/棋盘格无花屏），再查摄像头专属问题：

| 现象 | 优先检查 |
|------|----------|
| 彩色条纹、只有部分区块显示、帧率虚高 | DMA NDTR 是否仍为整帧长度（必须是一行 240 字）；DMA 是否 CIRCULAR + 行双缓冲 |
| 画面完全定格、CPU 占满 | 帧中断是否先清 `DCMI_FLAG_FRAMERI` 再重开 |
| 每 5s 一条横带错位 | 是否有任务用 `__disable_irq()` 长时间屏蔽 DCMI/DMA；应使用 `taskENTER_CRITICAL()` |
| 右栏闪烁/撕裂 | 是否往 LTDC 正在扫描的缓冲写像素；换帧是否只改 `CFBAR` 并置 `LTDC_SRCR_VBR` |
| 启动瞬间逐行填图 | 图层是否在首帧写满前就打开 |
| 右栏位置/尺寸不对 | 图层窗口是否为 x 320~800 / y 0~480，`WindowX1/WindowY1` 为右开区间 |
| 左栏全黑、右栏画面正常 | 顶层混合因子是否为 `CA`；必须为 `PAxCA` + `Alpha0=0`，且 `ltdc.c` 与 `cam_display_show()` 两处一致 |
| 相机区域采样点丢失（`eovr/esync` 增长） | DCMI GPIO 是否为 PULLUP + Very High；DMA 是否 HIGH + FIFO 1/2；与 LTDC/DMA2D 的 SDRAM 带宽争用 |

### 3.8 与其他任务的临界区约束

- 任何任务都不得用 `__disable_irq()` 长时间屏蔽中断；应使用 `taskENTER_CRITICAL()`（BASEPRI=5），屏蔽所有优先级数值 ≥5 的中断。当前工程为 SysTick/TIM7，DCMI/DMA2_Stream1（优先级 2）不受影响。
- 若用 `__disable_irq()` 屏蔽 DCMI/DMA 约 4ms，会吞掉约 15 行，表现为相机区域每 5s 出现一条横带错位。
- 各任务共享 SDRAM 带宽：若 `eovr/esync` 增长，先核对 DCMI GPIO 速度、DMA 优先级与 FIFO，再考虑降低其他总线主设备的占用。

## 4. 验证

先确认《02.LVGL移植方案.md》§6 的基础界面验收通过，再接摄像头：

1. 串口出现 `[cam] ov5640 id ok`、`[cam] sensor out=480x480 hts=... vts=...`、`[cam] capture started ...`、`[cam] init done`。
2. 右栏画面连续、无彩色条纹/横带错位；首帧后图层才打开，无逐行填图过程。
3. 每 2s 统计中 `fps` 稳定在目标值附近，`pub` 持续增长，`esync/eovr/dmaerr` 不增长。
4. 触摸、LED 开关、摄像头同时运行时无卡死、无花屏。
5. 其他外设联调不在本文范围；若相机每 5s 出现横带错位，优先复核 §3.8 的临界区约束。

## 5. 不做的事

- 不做 JPEG 输出、图像旋转/镜像、录像与存储。
- 不接入 DMA2D 做相机画面搬运（当前由硬件图层直接扫描）。
- 不做多分辨率动态切换；480×480 与 `CAM_IMG_W/H`、DMA 行字数、图层窗口三者绑定，改动需同步。
