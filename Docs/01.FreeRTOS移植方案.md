# FreeRTOS 移植方案（STM32F429IGT6 / Keil MDK-AC6）

> 硬件引脚与资源见《00.F429IGT6实验箱引脚说明.md》。

## 1. 概述

本文档描述将 FreeRTOS 移植到 STM32F429IGT6 工程的具体方案。FreeRTOS 内核源码取自 `Docs/FreeRTOS-LTS/FreeRTOS/FreeRTOS-Kernel`（Kernel V11.3.1），移植至独立目录 `FreeRTOS/`。

> **源码下载地址**：`https://github.com/FreeRTOS/FreeRTOS-LTS/releases/download/202604.01-LTS/FreeRTOSv202604.01-LTS.zip`（FreeRTOS 202604.01 LTS 官方包，本地参考副本 `Docs/FreeRTOSv202604.01-LTS.zip`，解压后内核位于 `FreeRTOS-Kernel/`）。

本次移植仅使用 FreeRTOS 原生 API，不引入 CMSIS-RTOS V2 封装。编译器由 ARMCC V5 切换至 ARM Compiler 6（AC6 / armclang），移植层使用 `portable/GCC/ARM_CM4F`，该目录下的 GCC 风格内联汇编在 AC6 下兼容。

移植完成后，建立可扩展的应用层模块结构（`App/`）。默认包含两个任务模块：LED 闪烁演示任务（`App/led/`）与串口调试任务（`App/uart/`），后续外设任务可按照相同结构扩展，避免 `main.c` 膨胀。

### 2.1 基础时钟方案

系统时钟树：HSE=25MHz，经 PLL（M=25、N=360、P=2）+ Overdrive 得到 **SYSCLK=180MHz**；AHB（HCLK）DIV1 → 180MHz，APB1 DIV4 → 45MHz（定时器时钟 ×2 → 90MHz），APB2 DIV2 → 90MHz（定时器时钟 ×2 → 180MHz）。

| 层 | 基础时钟 | 频率 | 喂时基方式 |
|----|---------|------|-----------|
| HAL | TIM7（APB1 定时器时钟 90MHz） | 1kHz | `TIM7_IRQHandler → HAL_TIM_IRQHandler → HAL_TIM_PeriodElapsedCallback → HAL_IncTick()` |
| FreeRTOS | SysTick（180MHz / 1000，reload=180000） | 1kHz | `SysTick_Handler → xPortSysTickHandler()` |

- **HAL 时基（TIM7）**：`stm32f4xx_hal_timebase_tim.c` 覆盖 `HAL_InitTick()`，TIM7 计数时钟 1MHz（预分频后）、周期 999 → **1ms 中断**驱动 `uwTick`。`main.c` 的 `HAL_TIM_PeriodElapsedCallback()` 在 TIM7 更新中断时调用 `HAL_IncTick()`，这是 `uwTick` 的**唯一**递增来源。`SysTick_Handler()` 只调用 `xPortSysTickHandler()`，**禁止**再调 `HAL_IncTick()`：两个 1kHz 中断同时喂 `uwTick` 会让 `HAL_GetTick()` 以 2 倍速度前进，`HAL_Delay()` 与所有 HAL 超时同步减半。
- **FreeRTOS 时基（SysTick）**：`configCPU_CLOCK_HZ = 180000000UL`、`configTICK_RATE_HZ = 1000` → SysTick reload=180000，**1ms 硬件 tick**。`SysTick_Handler()` 调用 `xPortSysTickHandler()` 推进内核 tick，任务切换由 PendSV（`xPortPendSVHandler`）完成；启动调度器时 SysTick 优先级被改写为 0x50（`configKERNEL_INTERRUPT_PRIORITY`），满足 `configMAX_SYSCALL_INTERRUPT_PRIORITY = 5<<4` 约束。

## 4. 详细改动

### 4.1 复制源码至 `FreeRTOS/`

| 目标 | 来源 |
|------|------|
| `FreeRTOS/Source/*.c` | Kernel 根目录 6 个 `.c` |
| `FreeRTOS/Source/include/*.h` | Kernel `include/` 全部 `.h` |
| `FreeRTOS/Source/portable/GCC/ARM_CM4F/{port.c, portmacro.h}` | Kernel 同名路径 |
| `FreeRTOS/Source/portable/MemMang/heap_4.c` | Kernel 同名路径 |

### 4.2 创建 `FreeRTOS/Config/FreeRTOSConfig.h`

以模板为基础定制。Cortex-M4 必须按 4 位优先级显式定义，不可照搬模板中的 0：

```c
#define configPRIO_BITS                                  4
#define configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY     5
#define configMAX_SYSCALL_INTERRUPT_PRIORITY             ( configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY << ( 8 - configPRIO_BITS ) )
#define configLIBRARY_KERNEL_INTERRUPT_PRIORITY          configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY
#define configKERNEL_INTERRUPT_PRIORITY                  ( configLIBRARY_KERNEL_INTERRUPT_PRIORITY << ( 8 - configPRIO_BITS ) )
```

其余配置项：

- `configCPU_CLOCK_HZ` 设为 `180000000UL`。
- `configTICK_RATE_HZ` 设为 `1000`。
- `configTOTAL_HEAP_SIZE` 设为 `65536`（64KB）。原 32KB 仅够基础任务运行，调大至 64KB 为上层应用（GUI 等）预留动态内存余量；本层不依赖上层功能，可独立运行。
- 功能开关：`configUSE_PREEMPTION 1`、`configUSE_TIME_SLICING 1`、`configMAX_PRIORITIES 32`、`configMINIMAL_STACK_SIZE 128`、`configUSE_TIMERS 1`、`configUSE_EVENT_GROUPS 1`、`configUSE_STREAM_BUFFERS 1`、`configUSE_MUTEXES 1`、`configUSE_RECURSIVE_MUTEXES 1`（预留递归互斥锁）、`configUSE_COUNTING_SEMAPHORES 1`。
- 软件定时器任务：`configTIMER_TASK_PRIORITY 5`、`configTIMER_TASK_STACK_DEPTH = 2 × configMINIMAL_STACK_SIZE`、`configTIMER_QUEUE_LENGTH 10`。
- 其余显式关闭项：`configUSE_TICKLESS_IDLE 0`、`configUSE_PORT_OPTIMISED_TASK_SELECTION 0`（沿用默认任务选择）。
- `configASSERT(x)` 定义为断言失败时 `taskDISABLE_INTERRUPTS()` 后死循环，便于定位异常（见第 8 节注意）。
- 分配方式：`configSUPPORT_STATIC_ALLOCATION 0`、`configSUPPORT_DYNAMIC_ALLOCATION 1`（纯 heap_4 动态分配）。
- `configCHECK_FOR_STACK_OVERFLOW` 设为 `2`（需提供 `vApplicationStackOverflowHook`）。
- `configUSE_IDLE_HOOK 0`、`configUSE_TICK_HOOK 0`。
- `configCHECK_HANDLER_INSTALLATION 0`（采用间接路由方式）。
- 删除模板中 ARMv8-M、MPU、TrustZone、SMP 相关项。
- `INCLUDE_*` 全部开启（含 `vTaskDelay`、`xTaskDelayUntil` 等）。

### 4.3 桥接中断（`Core/Src/stm32f4xx_it.c`，置于 USER CODE 区）

1. 在 `Includes` 区添加 `#include "FreeRTOS.h"`、`#include "task.h"`。
2. 在 `PFP`（私有函数原型）区添加 3 个 `extern` 原型。AC6 编译器要求显式声明，否则会报 `implicit-function-declaration` 错误（见第 8 节问题 1）：

   ```c
   extern void vPortSVCHandler( void );
   extern void xPortPendSVHandler( void );
   extern void xPortSysTickHandler( void );
   ```

3. 中断处理函数改为桥接至 FreeRTOS 对应函数：
   - `SVC_Handler()` 改为调用 `vPortSVCHandler();`
   - `PendSV_Handler()` 改为调用 `xPortPendSVHandler();`
   - `SysTick_Handler()` 只调用 `xPortSysTickHandler()`，不调用 `HAL_IncTick()`。

> **实测修正**：HAL 时基迁移到 TIM7 后，SysTick 只负责 FreeRTOS 的任务节拍。若在 SysTick 中重复调用 `HAL_IncTick()`，`uwTick` 变成 2kHz，`HAL_Delay(100)` 实际只等 50ms，串口统计打印间隔等所有基于 tick 的计时都会同步减半。反过来，只有在 SysTick 作为**唯一** HAL 时基且漏调 `HAL_IncTick()` 时，才会出现 `HAL_Delay()` 无限死等——这两种情况不能混为一谈。

### 4.4 建立 `App/` 应用模块层

设计目标：任务隔离与统一注册入口，`main.c` 只负责启动。

**4.4.1 `App/app_config.h`**，集中管理任务参数：

```c
#ifndef APP_CONFIG_H
#define APP_CONFIG_H
#include "FreeRTOS.h"

#define APP_LED_TASK_PRIORITY     1
#define APP_LED_TASK_STACK_SIZE   ( configMINIMAL_STACK_SIZE )
#define APP_LED_TOGGLE_MS         500

/* 串口调试任务 */
#define APP_UART_TASK_PRIORITY     2
#define APP_UART_TASK_STACK_SIZE   ( 2 * configMINIMAL_STACK_SIZE )
#define APP_UART_QUEUE_LEN         16   /* 消息队列深度（条） */
#define APP_UART_MAX_MSG_LEN       128  /* 单条消息最大字节数（含结束符） */
#define APP_UART_SEND_TIMEOUT      pdMS_TO_TICKS( 100 )  /* 入队等待时间，超时丢弃该条 */

#endif /* APP_CONFIG_H */
```

**4.4.2 `App/led/app_led.c/.h`**，LED 独立任务模块：

```c
/* app_led.h */
#ifndef APP_LED_H
#define APP_LED_H
void AppLed_TaskCreate(void);
#endif /* APP_LED_H */
```

```c
/* app_led.c */
#include "app_led.h"
#include "app_config.h"
#include "FreeRTOS.h"
#include "task.h"
#include "main.h"   /* LED0_Pin / LED0_GPIO_Port */

static void vLedTask(void *argument) {
  for (;;) {
    HAL_GPIO_TogglePin(LED0_GPIO_Port, LED0_Pin); /* PB1 */
    vTaskDelay(pdMS_TO_TICKS(APP_LED_TOGGLE_MS));
  }
}

void AppLed_TaskCreate(void) {
  xTaskCreate(vLedTask, "LED", APP_LED_TASK_STACK_SIZE, NULL, APP_LED_TASK_PRIORITY, NULL);
}
```

**4.4.3 `App/app_tasks.c/.h`**，统一任务启动入口：

```c
/* app_tasks.h */
#ifndef APP_TASKS_H
#define APP_TASKS_H
void AppTasks_Init(void);
#endif /* APP_TASKS_H */
```

```c
/* app_tasks.c */
#include "app_tasks.h"
#include "led/app_led.h"   /* 后续外设模块在此 include */
#include "uart/app_uart.h"

/* 栈溢出 hook，configCHECK_FOR_STACK_OVERFLOW=2 触发时进入死循环便于调试 */
void vApplicationStackOverflowHook(TaskHandle_t xTask, char *pcTaskName)
{
  (void)xTask; (void)pcTaskName;
  for (;;) {}
}

void AppTasks_Init(void) {
  AppLed_TaskCreate();    /* 新增任务只加一行 */
  AppUart_TaskCreate();   /* 串口调试任务 */
  /* 当前代码不在初始化处打印启动信息；串口链路可由各模块的首条日志验证 */
}
```

**4.4.4 精简 `main.c`**

```c
/* USER CODE BEGIN Includes */
#include "FreeRTOS.h"
#include "task.h"
#include "app_tasks.h"
/* USER CODE END Includes */
```

```c
/* USER CODE BEGIN 2 */
AppTasks_Init();           /* 创建所有任务 */
vTaskStartScheduler();     /* 启动后不再返回 */
/* USER CODE END 2 */
```

同时删除 `main.c` 中原有的 `vLEDTask` 函数及其原型（位于 `USER CODE BEGIN 4`、`PFP` 区）。

**4.4.5 `App/uart/app_uart.c/.h`**，串口调试任务模块：

串口使用已由 CubeMX 配置的 USART1（`huart1`，115200、8N1、PA9/PA10），在 `main.c` 中已调用 `MX_USART1_UART_Init()`，本模块不重复初始化外设，仅复用句柄。

```c
/* app_uart.h */
#ifndef APP_UART_H
#define APP_UART_H

void AppUart_TaskCreate(void);
void AppUart_Printf(const char *format, ...);

#endif /* APP_UART_H */
```

```c
/* app_uart.c */
#include "app_uart.h"
#include "app_config.h"
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include <stdarg.h>
#include <stdio.h>
#include <string.h>
#include "usart.h" /* huart1 */

static QueueHandle_t s_uartQueue = NULL;

/* 串口任务主体：阻塞等待消息，取出并发送 */
static void vUartTask(void *argument)
{
  (void)argument;
  char *pMsg;

  for (;;)
  {
    if (xQueueReceive(s_uartQueue, &pMsg, portMAX_DELAY) == pdPASS)
    {
      uint16_t len = (uint16_t)strlen(pMsg);
      if (len > 0U)
      {
        HAL_UART_Transmit(&huart1, (uint8_t *)pMsg, len, HAL_MAX_DELAY);
      }
      vPortFree(pMsg);
    }
  }
}

void AppUart_TaskCreate(void)
{
  s_uartQueue = xQueueCreate(APP_UART_QUEUE_LEN, sizeof(char *));
  if (s_uartQueue == NULL)
  {
    return;
  }
  xTaskCreate(vUartTask, "UART", APP_UART_TASK_STACK_SIZE, NULL,
              APP_UART_TASK_PRIORITY, NULL);
}

void AppUart_Printf(const char *format, ...)
{
  char *pMsg = pvPortMalloc(APP_UART_MAX_MSG_LEN);
  if (pMsg == NULL)
  {
    return;
  }

  va_list args;
  va_start(args, format);
  vsnprintf(pMsg, APP_UART_MAX_MSG_LEN, format, args);
  va_end(args);
  pMsg[APP_UART_MAX_MSG_LEN - 1U] = '\0';

  if (s_uartQueue == NULL)
  {
    /* 调度器未启动，直接同步发送 */
    uint16_t len = (uint16_t)strlen(pMsg);
    if (len > 0U)
    {
      HAL_UART_Transmit(&huart1, (uint8_t *)pMsg, len, HAL_MAX_DELAY);
    }
    vPortFree(pMsg);
    return;
  }

  if (xQueueSend(s_uartQueue, &pMsg, APP_UART_SEND_TIMEOUT) != pdPASS)
  {
    vPortFree(pMsg); /* 队列满，丢弃该条消息 */
  }
}
```

设计说明：任意任务调用 `AppUart_Printf()` 格式化字符串后放入消息队列，串口任务统一通过 USART1 异步发送，不阻塞调用方，且将串口硬件访问集中在单一任务内。队列满时入队等待 `APP_UART_SEND_TIMEOUT`，仍满则丢弃该条并释放内存。

## 5. 假设与决策

1. 目录采用镜像官方 `FreeRTOS/Source/{include, ...}` 结构，保留 `GCC/` 层级，便于对照官方源码定位与升级。
2. `FreeRTOSConfig.h` 独立存放于 `FreeRTOS/Config/`，不与内核头文件混放。
3. 仅使用 FreeRTOS 原生 API，不引入 `cmsis_os.h`，仅调用 `vTaskStartScheduler()`。
4. 应用任务统一放置于 `App/` 模块层，`main.c` 只调用 `AppTasks_Init()` 与 `vTaskStartScheduler()`。默认模块包括 LED 演示任务（`App/led/`）与串口调试任务（`App/uart/`），作为后续外设模块的样板。
5. 任务参数（优先级、栈、周期）集中由 `App/app_config.h` 管理。
6. Cortex-M4 中断优先级按 4 位显式定义，`configMAX_SYSCALL_INTERRUPT_PRIORITY` 对应阈值 5。该阈值只约束**在 ISR 内调用 FreeRTOS API 的中断**：这类中断的优先级数值必须 ≥5；不调用 RTOS API 的中断可以配置任意优先级（例如 TIM7=15），但其 ISR 内禁止调用任何 FreeRTOS API。
7. 使用纯 heap_4 动态分配，`configSUPPORT_STATIC_ALLOCATION=0`，无需实现 `vApplicationGetIdleTaskMemory` 等回调。`configCHECK_FOR_STACK_OVERFLOW=2`，需提供 `vApplicationStackOverflowHook`，置于 `app_tasks.c`。
8. 不重排启动向量表，通过 `stm32f4xx_it.c` 间接路由，因此 `configCHECK_HANDLER_INSTALLATION=0`。

## 6. 验证步骤

1. 在 Keil 中选择 AC6 重新编译，结果为 0 Error。
2. 链接通过，无 `vPortSVCHandler / xPortPendSVHandler / xPortSysTickHandler` 未定义错误。
3. AC6 下若 startup 汇编报错，更换 AC6 兼容 startup 后重新编译。
4. 验证 LED0（PB1）每 500ms 翻转一次，确认任务创建、调度器切换、`vTaskDelay` 延迟、SysTick 均正常工作。
5. 验证串口调试任务：连接 USART1（PA9/PA10，115200），任一模块调用 `AppUart_Printf()` 后应能收到输出（例如外设模块的初始化日志）。
6. 确认 HAL 时基未回归：`HAL_Delay()`、`HAL_GetTick()` 仍由 TIM7 驱动。
7. 核对在 ISR 内调用 FreeRTOS API 的中断满足优先级阈值；高于阈值的中断内不得调用 RTOS API。

## 7. 不做的事

- 不新增 CMSIS-RTOS V2 封装。
- 不改动 HAL 驱动及 usart、gpio 现有功能。
- 允许把已验证配置回填到 `.ioc`；回填后由 CubeMX 重新生成并复核 USER CODE 区。
- 除 USER CODE 区外，不改动其它 CubeMX 生成的逻辑。
- 本阶段不创建外设任务模块，只搭建 `App/` 框架并提供 LED 演示任务与串口调试任务样板。后续任务在需要时按框架在 `App/` 下扩展。

## 8. 实施中遇到的问题与修正

以下为从 AC5 切换至 AC6（armclang，严格 C99）后出现的编译、链接问题的实测修复记录。

### 问题 1：call to undeclared function 'xPortSysTickHandler'（-Wimplicit-function-declaration）

- 原因：`vPortSVCHandler`、`xPortPendSVHandler`、`xPortSysTickHandler` 仅定义于 `FreeRTOS/Source/portable/GCC/ARM_CM4F/port.c`，其原型只在对应 `.c` 文件内可见，公共头文件（`FreeRTOS.h`、`task.h`、`portmacro.h`）均不导出。AC5 允许隐式声明，AC6 则报错。
- 修复：在 `stm32f4xx_it.c` 的 `USER CODE BEGIN PFP` 区显式添加 3 个 `extern` 原型，见第 4.3 节。

### 问题 2：Undefined symbol vApplicationGetIdleTaskMemory / vApplicationGetTimerTaskMemory

- 原因：`configSUPPORT_STATIC_ALLOCATION=1` 时，内核强制要求这两个回调。
- 修复：本工程使用动态分配，将 `configSUPPORT_STATIC_ALLOCATION` 置为 `0`。若需静态分配，则必须实现这两个回调（返回预分配的 TCB 与栈内存）。

### 问题 3：Undefined symbol vApplicationStackOverflowHook

- 原因：`configCHECK_FOR_STACK_OVERFLOW=2` 开启栈溢出检测，内核要求该 hook。
- 修复：在 `App/app_tasks.c` 中提供 `vApplicationStackOverflowHook`，触发时进入死循环便于调试。若不需要该检测，可将 `configCHECK_FOR_STACK_OVERFLOW` 置为 `0` 并删除 hook。

### 问题 4：任务无法切换，LED 不闪烁（PendSV_Handler 未桥接）

- 现象：程序能下载运行，但任务只执行一次便停止，演示任务不工作（如 LED 不闪烁）。
- 原因：SVC、SysTick 已桥接，但 `stm32f4xx_it.c` 中的 `PendSV_Handler()` 漏掉调用 `xPortPendSVHandler()`。FreeRTOS 的所有上下文切换均由 PendSV 完成，该中断被空实现接管后，调度器无法执行任务切换，任务一旦阻塞便无法恢复。
- 修复：在 `PendSV_Handler()` 中补上 `xPortPendSVHandler();`（置于 USER CODE 区）。三者桥接必须齐全：SVC→`vPortSVCHandler`、PendSV→`xPortPendSVHandler`、SysTick→`xPortSysTickHandler`。

### 其他注意

- AC6 下若 `startup_stm32f429xx.s` 汇编报错，改用 MDK 自带的 AC6 兼容 startup。
- 需核对 NVIC 阈值只作用于“会在 ISR 内调用 FreeRTOS API”的中断：其优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`（5 << 4）。不调用 RTOS API 的中断可以配置更高抢占优先级，但其 ISR 内不得调用任何 FreeRTOS API。
