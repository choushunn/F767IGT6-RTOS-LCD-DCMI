### 1.1 与本工程（F767IGT6-RTOS-LVGL-LCD-DCMI）的差异

本工程只借用参考工程的引脚与外设映射，运行时行为已按 RTOS + LVGL 架构重写，下表为实际差异（代码为准）：

| 项目 | 参考工程（实验46） | 本工程现状 |
|---|---|---|
| SD 卡 / NAND | SDMMC1 + NAND，PC8/9/11 与 DCMI 分时复用 | **未使用**，PC8/9/11 固定为 DCMI |
| 摄像头输出 | 1280x720 / JPEG + RGB565 两套 | **480x480 RGB565 @15fps**，DMA2_Stream1 按行搬运（NDTR=240 字/行） |
| 画面显示 | 单层 LTDC，整屏写帧缓冲 | **图层 0 左栏 320 + 图层 2 相机窗口 320~800**，相机三缓冲轮换 |
| 蜂鸣器 | 参考工程实验未使用 | **PCF8574 P0，由 LVGL 开关控制（低电平响）** |
| 触摸 | 未涉及 | **GT1151 电容触摸**，SCL=PH6 / SDA=PI3 / RST=PI8 / INT=PH7（见《03.触摸移植方案.md》） |
| 画面方向 | 未处理 | 用传感器内置镜像/翻转寄存器纠正（`CAM_MIRROR_H` / `CAM_FLIP_V`） |
| 帧率计时 | TIM3 定时打印 | TIM7 作为 HAL 1ms 时基；帧率由 DMA 行中断统计（`pub`） |
| LED / 按键 | PB1/PB0、PH3/PH2/PC13/PA0 | 一致（LED 低电平点亮） |

## 2. 摄像头子系统

### 2.1 DCMI 并口（8 位）

配置位置：[dcmi.c](file:///d:/Embedded/STM32/F767IGT6-RTOS-LVGL-LCD-DCMI/Docs/%E5%AE%9E%E9%AA%8C46%20%E7%85%A7%E7%9B%B8%E6%9C%BA%E5%AE%9E%E9%AA%8C/HARDWARE/DCMI/dcmi.c#L47-L86) 的 `HAL_DCMI_MspInit()`。

统一配置：`GPIO_MODE_AF_PP`、`GPIO_PULLUP`、`GPIO_SPEED_HIGH`、`GPIO_AF13_DCMI`。

| DCMI 信号 | MCU 引脚 | 说明 |
|---|---|---|
| DCMI_PIXCLK | PA6 | 像素时钟 |
| DCMI_VSYNC | PB7 | 场同步 |
| DCMI_HSYNC（HREF） | PH8 | 行同步；`readme.txt` 写的是 PH7，与代码不一致，以代码 PH8 为准 |
| DCMI_D0 | PC6 | 数据位 0 |
| DCMI_D1 | PC7 | 数据位 1 |
| DCMI_D2 | PC8 | 与 SDMMC1_D0 复用 |
| DCMI_D3 | PC9 | 与 SDMMC1_D1 复用 |
| DCMI_D4 | PC11 | 与 SDMMC1_D3 复用 |
| DCMI_D5 | PD3 | 数据位 5 |
| DCMI_D6 | PB8 | 数据位 6 |
| DCMI_D7 | PB9 | 数据位 7 |

`readme.txt` 给出的 OV5640 模块侧接线为：

```
OV_D0~D7  -> PB8 / PB9 / PD3 / PC11 / PC9 / PC8 / PC7 / PC6
OV_SCL    -> PB4
OV_SDA    -> PB3
OV_VSYNC  -> PB7
OV_HREF   -> PH7      （代码实际初始化 PH8）
OV_RESET  -> PA15
OV_PCLK   -> PA6
OV_PWDN   -> PCF8574_P2
```

注意：按 readme 的顺序，模块的 `OV_D0` 对应到 `DCMI_D6`，位序与 DCMI 编号相反；此类文档通常按 `OV_D7→D0` 书写，建议以模块原理图核对一次。

### 2.2 OV5640 复位与电源

| 信号 | 引脚 / 控制方式 | 配置 |
|---|---|---|
| OV5640_RESET | PA15 | 推挽输出、上拉、高速 |
| OV5640_PWDN | PCF8574 的 P2 位 | 通过软件 I²C 写 PCF8574 |
| SCCB_SCL | PB4 | 推挽输出、上拉、快速 |
| SCCB_SDA | PB3 | 推挽输出，读时切换为输入 |

- `OV5640_Init()` 先配置 PA15，再 `OV5640_RST(0)` → `PWDN=0` → `OV5640_RST(1)`，最后初始化 SCCB。
- PB3/PB4/PA15 复位后默认是 JTAG 引脚（JTDO/NJTRST/JTDI），本例把它们当普通 GPIO 使用，因此调试只能使用 **SWD（PA13/PA14）**。

### 2.3 PCF8574（I²C 扩展 IO）

| R5 | PH11 | 红色数据 |
| R6 | PH12 | 红色数据 |
| R7 | PG6 | 兼作面板 ID 的 M0 |
| G2 | PH13 | 绿色数据 |
| G3 | PH14 | 绿色数据 |
| G4 | PH15 | 绿色数据 |
| G5 | PI0 | 绿色数据 |
| G6 | PI1 | 绿色数据 |
| G7 | PI2 | 兼作面板 ID 的 M1 |
| B3 | PG11 | 蓝色数据 |
| B4 | PI4 | 蓝色数据 |
| B5 | PI5 | 蓝色数据 |
| B6 | PI6 | 蓝色数据 |
| B7 | PI7 | 兼作面板 ID 的 M2 |
| LTDC_DE | PF10 | 数据使能 |
| LTDC_CLK | PG7 | 像素时钟 |
| LTDC_HSYNC | PI10 | 水平同步 |
| LTDC_VSYNC | PI9 | 垂直同步 |

说明：

- 代码注释明确给出 `PG6=R7(M0)、PI2=G7(M1)、PI7=B7(M2)`；`PI9/PI10 = VSYNC/HSYNC` 与同型号 MCU 的 CubeMX 工程一致；R3~R6、B3~B6 按 STM32F767 AF14 映射整理，移植前建议再对照底板原理图核对一次。
- 采用 **RGB565（16 位数据）**：R3~R7 + G2~G7 + B3~B7，加 DE/CLK/HSYNC/VSYNC 共 20 根 LTDC 引脚。
- 像素格式由 `LCD_PIXFORMAT = LCD_PIXEL_FORMAT_RGB565` 指定，帧缓存固定放在 SDRAM 起始地址 `0xC0000000`（[ltdc.h](file:///d:/Embedded/STM32/F767IGT6-RTOS-LVGL-LCD-DCMI/Docs/%E5%AE%9E%E9%AA%8C46%20%E7%85%A7%E7%9B%B8%E6%9C%BA%E5%AE%9E%E9%AA%8C/HARDWARE/LCD/ltdc.h#L59-L63)）。
- 背光默认点亮：`LCD_LED(1)`。

### 3.2 面板 ID 识别

`LTDC_PanelID_Read()` 在 LTDC 初始化前把三根线切成**上拉输入**读取面板型号，随后 `LTDC_Init()` 再把它们切回 AF14 数据输出：

| ID 位 | 引脚 | 对应信号 |
|---|---|---|
| M0 | PG6 | R7 |
| M1 | PI2 | G7 |
| M2 | PI7 | B7 |

| M2:M1:M0 | 面板 ID | 分辨率 |
|---|---|---|
| 000 | 0x4342 | 4.3 寸 480×272 |
| 001 | 0x7084 | 7 寸 800×480 |
| 010 | 0x7016 | 7 寸 1024×600 |
| 011 | 0x7018 | 7 寸 1280×800 |
| 100 | 0x4384 | 4.3 寸 800×480 |
| 101 | 0x1018 | 10.1 寸 1280×800 |

### 3.3 MCU 屏兼容分支（FSMC）

当未检测到 RGB 屏（面板 ID 为 0）时，`LCD_Init()` 走 FSMC 分支（[lcd.c](file:///d:/Embedded/STM32/F767IGT6-RTOS-LVGL-LCD-DCMI/Docs/%E5%AE%9E%E9%AA%8C46%20%E7%85%A7%E7%9B%B8%E6%9C%BA%E5%AE%9E%E9%AA%8C/HARDWARE/LCD/lcd.c#L679-L721)），使用 FMC BANK1/NE1、16 位数据宽度：

| 功能 | 引脚 |

| D0~D1 | PD14、PD15 |
| D2~D3 | PD0、PD1 |
| D4~D12 | PE7~PE15 |
| D13~D15 | PD8、PD9、PD10 |
| NOE / NWE | PD4 / PD5 |
| NE1（片选） | PD7 |

## 6. 引脚复用与冲突

| 引脚 | 用途 A | 用途 B | 处理方式 |
|---|---|---|---|
| PC8 | DCMI_D2 | SDMMC1_D0 | 运行时切换 AF13 / AF12 |
| PC9 | DCMI_D3 | SDMMC1_D1 | 运行时切换 AF13 / AF12 |
| PC11 | DCMI_D4 | SDMMC1_D3 | 运行时切换 AF13 / AF12 |
| PG6 | LTDC_R7 | 面板 ID M0 | 上电读 ID 后切 AF14 |
| PI2 | LTDC_G7 | 面板 ID M1 | 上电读 ID 后切 AF14 |
| PI7 | LTDC_B7 | 面板 ID M2 | 上电读 ID 后切 AF14 |
| PD0/PD1/PD4/PD5/PD8~PD15、PE7~PE15 | SDRAM / NAND 数据与控制 | MCU 屏 FSMC | 通过不同片选（SDNE0 / NCE3 / NE1）区分 |
| PB3 / PB4 / PA15 | SCCB_SDA / SCCB_SCL / OV_RESET | JTAG（JTDO/NJTRST/JTDI） | 只能使用 SWD 调试 |
| PB5 | LCD 背光 | — | 普通 GPIO |
| PB6 | QSPI_NCS | I²C1_SCL 等 | 本例仅作 QSPI |

### 摄像头与 SD 卡的分时复用

`main.c` 中通过两个函数动态切换 PC8/PC9/PC11 的复用功能，并同时开关 OV5640 输出，避免总线冲突：

- `sw_ov5640_mode()`：写 OV5640 寄存器 `0x3017/0x3018 = 0xFF`，PC8/9/11 切为 `GPIO_AF13_DCMI`。
- `sw_sdcard_mode()`：写 `0x3017/0x3018 = 0x00` 关闭摄像头输出，PC8/9/11 切为 `GPIO_AF12_SDMMC1`。

拍照流程为：切 SD 卡模式 → 写文件 → 切回摄像头模式 → 恢复 DCMI 显示。因此在 DCMI 连续采集期间不能直接访问 SD 卡。

## 7. 初始化顺序（引脚相关）

`main()` 中的关键顺序（[main.c](file:///d:/Embedded/STM32/F767IGT6-RTOS-LVGL-LCD-DCMI/Docs/%E5%AE%9E%E9%AA%8C46%20%E7%85%A7%E7%9B%B8%E6%9C%BA%E5%AE%9E%E9%AA%8C/USER/main.c#L245-L356)）：

3. `uart_init(115200)`：PA9/PA10
4. `LED_Init()`、`KEY_Init()`
5. `SDRAM_Init()`：FMC 39 根线，帧缓存基址 `0xC0000000`
6. `LCD_Init()`：先读面板 ID（PG6/PI2/PI7 输入），再初始化 LTDC 或 FSMC
7. `PCF8574_Init()`：PH4/PH5 + PB12
8. `OV5640_Init()`：PA15 复位、PCF8574 P2 上电、PB3/PB4 SCCB 读 ID
9. `sw_sdcard_mode()`：PC8/9/11 先切到 SDMMC1
10. `W25QXX_Init()`：QSPI
11. `f_mount()` 挂载 SD 卡，检查字库
12. 申请 JPEG 缓冲 → 再次初始化 OV5640（RGB565）→ `DCMI_Init()` → `DCMI_DMA_Init()` → `DCMI_Start()`

依赖关系：LTDC 依赖 SDRAM 作为显存；OV5640 依赖 PCF8574 的 PWDN 和 SCCB；DCMI 依赖 PC8/9/11 已切回 AF13。

## 8. 疑点与注意事项

1. **HREF 引脚不一致**：`readme.txt` 写 `OV_HREF → PH7`，代码实际配置 `PH8`（DCMI_HSYNC）。F767 的 DCMI_HSYNC 可用引脚中 PH7 并不承担该功能，应以代码 PH8 为准。
2. **摄像头数据位序**：readme 的 `OV_D0~D7` 列表与 DCMI 的 D0~D7 编号相反，建议对照 OV5640 模块原理图确认，避免出现图像花屏。
3. **JTAG 引脚被占用**：PB3、PB4、PA15 被用作 SCCB 和复位，必须使用 SWD 调试；若需 JTAG，需要另行调整引脚。
4. **DCMI 与 SDMMC 不能同时使用**：PC8/PC9/PC11 三根线是共享的，必须按 `sw_ov5640_mode()` / `sw_sdcard_mode()` 切换。
5. **面板 ID 与 RGB 数据共用引脚**：PG6/PI2/PI7 在 LTDC 启动后是数据输出，不能再当普通输入读取。
6. **FMC 总线共享**：SDRAM、NAND、MCU 屏都挂在 FMC 上，共用数据/地址线；新增外设时不要重复占用这些引脚。
7. **根目录 .ioc 已同步**：`F767IGT6-RTOS-LVGL-LCD-DCMI.ioc` 已写入 DCMI、LTDC、SDRAM、QSPI、USART1、LED/KEY、SCCB、软件 IIC 等引脚，并移除了 SDMMC 专用引脚 PC10/PC12/PD2；PC8/PC9/PC11 保留为 DCMI。**NAND 未写入 .ioc**：CubeMX 把 FMC 的 NOR/NAND/SDRAM 建模为互斥模式（顶层 XOR），SDRAM 与 NAND 不能同时勾选；为保证 LTDC 显存，.ioc 保留 SDRAM。NAND 仍可按示例 `nand.c` 在代码中单独初始化。FMC 已按示例配置为 SDRAM BANK1（PC2/PC3）、13 位地址、16 位数据、4 BANK、CAS3、SDCLK=HCLK/2，并补齐 NBL0/NBL1（`Sd2ByteEnable1`）。原文件备份为同目录 `.ioc.bak`。
