# 触摸移植方案（GT1151 / 软件 I2C / LVGL 输入设备）

> 引脚与电气特性见《实验46 照相机实验_引脚配置分析.md》。

> **前提**：本文描述 ATK-7084 电容触摸屏的触摸芯片移植方案，前置条件是 FreeRTOS 与 LVGL 均已成功移植（详见《02.LVGL移植方案.md》）。
> 触摸芯片经**软件模拟 I2C** 接入，运行时探测芯片型号，坐标读取接入 LVGL 输入设备回调。

**当前状态**：芯片已确认并正常识别为 **GT1151**（探测命中地址 **0x5D**，ID 0x31313538）。面板原始坐标为 1024x600；实机确认竖屏安装方向需要使用 270° 显示旋转，触摸驱动仍上报物理坐标，由 LVGL v9 输入层自动转换到 600x1024 逻辑坐标。串口输出 `[TOUCH] GT9xxx detected` / `not found`。

## 1. 概述

| 项目 | 说明 |
|------|------|
| 屏幕 | 正点原子 ATK-7016，7 寸 1024x600 RGB 电容触摸屏 |
| 触摸芯片 | 汇顶 GT1151（GT9xxx 系列，**I2C 模式**，非 SPI） |
| 通信方式 | 软件模拟 I2C（GPIO 位操作，开漏 + 内部上拉） |
| 总线速率 | 约 100~200kHz（低于 GT9xxx 的 400kHz 上限） |
| I2C 从机地址 | 0x5D（复位释放瞬间 INT 拉低锁定；INT 高时为 0x14，双地址探测均可命中） |
| 探测方式 | 读 0x8140 产品 ID（4 字节 ASCII）匹配型号 |

### 1.1 基础时钟方案

触摸模块**不占用独立硬件时钟**，时序全部依赖 HAL 时基与 LVGL 任务节奏：

- **时序来源**：软件 I2C 翻转、复位等待（≥100ms）等延时的 `HAL_Delay()` / `HAL_GetTick()` 由 HAL 时基驱动——`uwTick` 只由 TIM7（1ms 中断）经 `HAL_TIM_PeriodElapsedCallback → HAL_IncTick()` 递增；`SysTick_Handler` 只推进 FreeRTOS 任务节拍，不得再调 `HAL_IncTick()`（详见《01.FreeRTOS移植方案.md》§2.1）。
- **坐标采集节奏**：`Touch_Scan()` 在 LVGL 输入设备回调 `lv_port_indev_read_cb()` 内调用，由 LVGL 任务按 `APP_LVGL_PERIOD_MS`（5ms）经 `lv_timer_handler()` 周期读取（详见《02.LVGL移植方案.md》§4.5）。

## 2. 硬件引脚

| 功能 | 引脚 | 电平 / 说明 |
|------|------|-------------|
| I2C SCL | PH6 | 开漏输出 + 内部上拉 |
| I2C SDA | PI3 | 开漏输出 + 内部上拉 |
| 复位 RST | PI8 | 低电平复位 |
| 中断 INT | PH7 | 复位时拉低锁地址，复位后恢复输入 |

> 已验证上述引脚与 LTDC 显示接口**无冲突**，可安全用于软件 I2C 触摸探测。
>
> 同一组触摸接口引脚预留给电阻屏 XPT2046（软件 SPI）：CLK=PH6、MOSI=PI3、MISO=PG3、CS=PI8、PEN=PH7，与电容屏为二选一接法；两类引脚定义统一集中于 `App/touch/touch_pins.h`。当前方案仅使用电容屏（GT9xxx I2C），电阻屏引脚仅为预留。
>
> 允许把已验证的触摸引脚静态配置回填到 `.ioc`；回填后由 CubeMX 重新生成并复核 `touch_pins.h`。

## 3. 软件实现

> 代码位于 `App/touch/`：`touch_detect.c/.h`（软件 I2C 时序原语、芯片复位与探测、坐标读取）、`touch_pins.h`（电容屏 GT9xxx 与电阻屏 XPT2046 的引脚集中定义）。

### 3.1 软件 I2C 底层（GPIO 位带时序）

`touch_detect.c` 用 GPIO 位带模拟 I2C 主机，不依赖硬件 I2C 外设：

- **引脚模式**：SCL / SDA 均配置为**开漏输出 + 内部上拉**；SDA 在读位与 ACK 阶段需在「输入（读）」与「开漏输出（写）」间动态切换（`touch_sda_set_input / touch_sda_set_output`）。
- **速率控制**：每个位翻转间空转 `touch_i2c_delay()`（约 300 个时钟周期），把总线速率压到 100~200kHz，低于 GT9xxx 的 400kHz 上限，避免探测失败。
- **时序原语**：START（SCL 高电平期间 SDA 拉低）、STOP（SCL 高电平期间 SDA 拉高）、发送字节（MSB 先行，第 9 个时钟读从机 ACK）、接收字节（主机回 ACK 继续 / NACK 结束）。
- **寄存器寻址**：支持 8-bit 与 16-bit（高字节在前）两种寄存器地址，提供读/写三种原语 `touch_i2c_read_reg8 / touch_i2c_read_reg16 / touch_i2c_write_reg16`；GT9xxx 的 PID/触点状态/坐标/控制寄存器均走 16-bit 寻址。
- **失败处理**：任一阶段从机 NACK 立即 STOP 并返回失败，调用方跳过该地址继续探测。

### 3.2 探测流程 `Touch_Detect()`

1. 软件 I2C 初始化：SCL / SDA 配置为**开漏输出 + 内部上拉**（无外部上拉时总线才能正常拉高）。
2. 单次硬复位（探测期间不再重复复位）：
   - RST 拉低，INT 拉低（锁定从机地址 0x5D）；
   - RST 拉高，**延时 ≥100ms** 等待 GT911 系芯片内部初始化完成（期间不响应 I2C 请求，过短的复位等待会导致探测失败）；
   - INT 恢复为输入，用于接收触摸中断。
3. 依次尝试两个候选地址，读 `0x8140` 产品 ID（4 字节 ASCII），与 GT911 / GT9147 / GT1151 / GT9271 的 ID 逐一比对。两个地址是同一芯片在不同 INT 电平下的表现，不是两个设备：

   ```c
   #define GT9XXX_ADDR_A   0x14U   /* INT=高时的 GT911/9147 地址 */
   #define GT9XXX_ADDR_B   0x5DU   /* INT=低时的 GT911/9147 地址 */
   ```
4. 当前模块命中：**GT1151**，ID = `0x31313538`（ASCII "1158"），I2C 地址 **0x5D**。
5. **软复位**（官方时序）：向控制寄存器 `0x8040` 写 `0x02` → 延时 10ms → 写 `0x00`。硬复位 + ID 识别后必须执行此序列，芯片才会进入正常触摸工作状态并输出坐标（否则 GSTID 寄存器始终无触点）。

### 3.3 坐标读取 `Touch_Scan()`

- 读 `0x814E` 触点状态：bit7 = 坐标缓冲就绪（读后写 0 清除，防止重复读到旧帧），bit3:0 = 本次触点个数；
- 读 `0x8150` 第 1 触点坐标 4 字节：`x_lo, x_hi, y_lo, y_hi`；
- 原始坐标读取与钳位：

```c
uint16_t raw_x = (uint16_t)(((uint16_t)buf[1] << 8) | buf[0]);
uint16_t raw_y = (uint16_t)(((uint16_t)buf[3] << 8) | buf[2]);

/* Touch_Scan 返回物理面板原始 1024x600 坐标。 */
uint16_t pos_x = (uint16_t)((raw_x < 1024U) ? raw_x : 1023U);
uint16_t pos_y = (uint16_t)((raw_y < 600U) ? raw_y : 599U);
```

> `Touch_Scan()` 和 LVGL 输入回调都保持在物理坐标层，不做显示旋转。LVGL v9 的 `indev_pointer_proc()` 会根据显示旋转自动转换坐标；回调内再次旋转会造成双重旋转。

### 3.4 LVGL 输入设备接入（`LVGL/lv_port_indev.c`）

`lv_port_indev_init()` 先做一次探测并打印结果，失败也照常注册输入设备（只是始终 `RELEASED`）：

```c
void lv_port_indev_init(void)
{
  lv_indev_t *indev;
  uint8_t detected = Touch_Detect();

  AppUart_Printf("[TOUCH] GT9xxx %s\r\n", (detected != 0U) ? "detected" : "not found");

  indev = lv_indev_create();
  lv_indev_set_type(indev, LV_INDEV_TYPE_POINTER);
  lv_indev_set_read_cb(indev, lv_port_indev_read_cb);
}
```

`lv_port_indev_read_cb()` 调用 `Touch_Scan()`，把物理坐标转换成逻辑坐标，有触点时置 `LV_INDEV_STATE_PRESSED`，否则置 `RELEASED`：

```c
static void lv_port_indev_read_cb(lv_indev_t *indev, lv_indev_data_t *data)
{
    uint16_t x = 0U;
    uint16_t y = 0U;

    if (Touch_Scan(&x, &y) != 0U)
    {
        data->state = LV_INDEV_STATE_PRESSED;
        data->point.x = x;
        data->point.y = y;
    }
    else
    {
        data->state = LV_INDEV_STATE_RELEASED;
    }

    data->continue_reading = false;
}
```

## 4. 关键修复记录

| # | 问题 | 根因 / 修复 |
|---|------|-------------|
| 1 | 串口完全无输出、HAL_Delay() 死等 | SysTick 作为唯一 HAL 时基时漏调 `HAL_IncTick()`。修复：当时在 SysTick 中补调 `HAL_IncTick()`。该做法已被后续的 TIM7 时基方案取代——现在 SysTick 只调 `xPortSysTickHandler()`，再喂 HAL 会让 `uwTick` 变成 2kHz（见《01.FreeRTOS移植方案.md》§4.3） |
| 2 | 软件 I2C 总线无法拉高 | 未配置内部上拉。修复：SCL/SDA 开漏 + 内部上拉 |
| 3 | GT911 系探测失败 | 复位释放后未等 100ms 就发 I2C。修复：复位后延时 ≥100ms 再读 PID |
| 4 | 触摸“无反应”、触点点不中控件 | 不要自行旋转输入坐标。LVGL v9 输入层会根据显示旋转自动转换；若实机方向相反，与显示一起切换为 270° |
| 5 | LVGL 首次渲染 HardFault | LVGL 内存池 16KB 不足导致控件创建失败返回 NULL。修复：详见《02.LVGL移植方案.md》第 8 节问题 3 |
| 6 | 硬复位 + ID 识别后无触摸坐标 | 缺少官方软复位序列（写 `0x8040=0x02`→10ms→`0x00`），芯片未进入正常触摸工作态。修复：`Touch_Detect()` 命中 GT9xxx 后调用 `touch_gt9xxx_soft_reset()` |
| 7 | 竖屏界面可见但按钮点不中 | 确认回调上报的是原始 1024×600 物理坐标，并且没有额外旋转；LVGL 输入层会自动匹配当前显示旋转 |

## 5. 验证

1. 串口日志确认：`[TOUCH] GT9xxx detected`（未命中时为 `not found`）。
2. 600×1024 竖屏界面正常渲染；物理竖放后，点击“开始上机 / 开始拍照 / 完成上机”与界面位置一致。
3. **Switch 触摸切换 LED1（PB0）**：拨开 Switch → LED1 点亮（低电平点亮，代码写 `GPIO_PIN_RESET`），拨回 → 熄灭。LED0（PB1）闪烁仍由 `app_led` 任务独立驱动。
4. UI 设计阶段相机图层关闭，点击预览占位区域不应产生操作。
5. LVGL 任务（优先级 4）与 LED、串口、相机采集协同调度，无卡死；相机 15fps 采集时触摸仍正常。
