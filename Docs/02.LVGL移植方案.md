# LVGL 移植与验证方案（v9 / LTDC 并口 RGB / 1024x600 原生屏 / 600x1024 竖屏 / RGB565 / FreeRTOS / AC6）

> 硬件引脚与资源见《实验46 照相机实验_引脚配置分析.md》。

> **前提**：本文描述 LVGL v9 移植方案，**前置条件是 FreeRTOS 已成功移植**（详见《01.FreeRTOS移植方案.md》）。
> 本方案依赖以下 FreeRTOS 已就绪的能力：
> - HAL 时基由 TIM7 提供（见 §2.1），`SysTick_Handler` 只桥接 `xPortSysTickHandler()`，不再喂 `HAL_IncTick()`；
> - `heap_4.c` 动态内存分配可用；
> - `App/` 应用任务框架与 `AppTasks_Init()` 统一注册入口；
> - AC6（armclang）编译通过、中断桥接齐全。
>
> 若 FreeRTOS 尚未就绪，应先行完成其移植与验证，再回到本文。

> 目标：将 LVGL v9.x 输出到物理竖放的 LTDC 1024x600 面板，逻辑坐标为 **600x1024**。LVGL 先按原生 1024x600 创建显示并应用实机确认的 270° 旋转，PARTIAL 局部缓冲仍在内部 SRAM；flush 使用 `lv_display_rotate_area()` + `lv_draw_rotate()` 写入外部 SDRAM。相机图层只在预览状态开启。
> 本文只负责 LVGL 竖屏移植、授权界面显示与触摸验证；摄像头见《04.DCMI摄像头模块方案.md》。
> 输入层已接入 GT9xxx 电容触摸（详见《03.触摸移植方案.md》）。

**当前状态**：显示移植层、270° 显示/触摸坐标转换、任务框架、600x1024 六态授权界面和按需相机预览已接入。待机不采集；点击“开始上机”启动预览，点击“开始拍照”冻结照片，确认后再点击“开始验证”。

**DMA2D 状态**：`MX_DMA2D_Init()` 已完成硬件初始化；LVGL 侧 draw unit 已接入但当前暂关闭（`LV_USE_DRAW_DMA2D = 0`），验证 LTDC/SDRAM 显示链路后再置 1，接入方法见 §4.7。

## 1. 概述

LVGL v9 源码取自参考副本 `Docs/lvgl-v9.6.0-lite`，移植至独立目录 `LVGL/`，其中：

> **源码下载地址**：`https://github.com/lvgl/lvgl/releases/download/v9.6.0/lvgl-v9.6.0-lite.zip`（LVGL v9.6.0 官方 Release 资产，本地参考副本 `Docs/lvgl-v9.6.0-lite.zip`，解压后源码位于 `lvgl/`）。

- `LVGL/lvgl/`：LVGL 官方源码（`src/`、`include/` 等），剔除 `examples`、`demos`；
- `LVGL/lv_conf.h`：LVGL 配置；
- `LVGL/lv_port_disp.c/.h`：显示移植层（LTDC + SDRAM 帧缓冲）；
- `LVGL/lv_port_indev.c/.h`：输入移植层（指针型输入设备，接入 GT9xxx 触摸）。

LVGL 与 FreeRTOS 的桥接采用「LVGL 任务 + 原生 FreeRTOS API」方式，不引入 CMSIS-RTOS：`lv_init()` 在 LVGL 任务内调用一次，通过 `lv_timer_handler()` 周期推进渲染，配合 FreeRTOS 调度。LVGL 内部 OS 层配置为 `LV_OS_NONE`，渲染在 LVGL 任务内同步完成；曾使用 `LV_OS_FREERTOS`（独立 swdraw 渲染线程），但其任务通知握手在调度交错时会丢信号并导致 `lv_timer_handler()` 永久阻塞，故回退为单任务内联渲染（见 §8 问题 4）。

| 输入移植层 | `LVGL/lv_port_indev.c`（指针型输入设备，接入 GT9xxx 触摸） |

| 工程文件 | `MDK-ARM/F767IGT6-RTOS-LVGL-LCD-DCMI.uvprojx` |

LVGL 帧缓冲按 1024×600×2（RGB565）= 1228800 B（1.2 MB）预留，必须放外部 SDRAM；内部 SRAM 仅用于 RTOS 堆、LVGL 任务栈和 64KB 局部渲染缓冲。相机另占三块 512×512×2 = 524288 B 的帧缓冲（见《04.DCMI摄像头模块方案.md》）。

`main.c` 实际初始化顺序：`MX_GPIO_Init()` → `MX_DCMI_Init()` → `MX_DMA2D_Init()` → `MX_FMC_Init()` → `MX_LTDC_Init()` → `MX_QUADSPI_Init()` → `MX_USART1_UART_Init()`，随后 `AppTasks_Init()`（内部先 `AppCamera_Init()`，再创建 LED / UART / LVGL 任务）→ `vTaskStartScheduler()`。**FMC 必须先于 LTDC**：SDRAM 上电序列完成后，LTDC 才能在有效帧缓冲上开始扫描。

**上电清屏 + LCD 背光使能**：`main.c` 的 USER CODE 2 区顺序固定为

1. 先把 LED0/LED1 写高（低电平点亮，即熄灭）；
2. 把 `0xC0000000` 起的 1024×600×2B（按全屏上限）帧缓冲整块清零——SDRAM 复位后内容不确定，而 LTDC 此刻已在扫描，直接点背光会看到上一次运行的残留画面；
3. 再执行 `HAL_GPIO_WritePin(LCD_BL_GPIO_Port, LCD_BL_Pin, GPIO_PIN_SET)`（PB5 高电平点亮背光）；
4. 最后 `AppTasks_Init()` → `vTaskStartScheduler()`。

省略清屏会在开机瞬间看到上次运行的旧画面；省略背光则 LTDC 有信号但整屏黑。

### 2.1 基础时钟方案

时钟树与 HAL/RTOS 时基沿用《01.FreeRTOS移植方案.md》§2.1：HSE=25MHz → PLL → SYSCLK=216MHz，HAL 时基 TIM7（1ms）、FreeRTOS 时基 SysTick（1ms）。LVGL 在此之上**不占用独立硬件定时器**，tick 直接复用 SysTick（FreeRTOS）：

| 层 | 基础时钟 | 频率 | 喂时基方式 |
|----|---------|------|-----------|
| HAL | TIM7（APB1 定时器时钟 108MHz） | 1kHz | `HAL_TIM_PeriodElapsedCallback → HAL_IncTick()`（SysTick 不参与 HAL 计时） |
| FreeRTOS | SysTick（216MHz / 1000） | 1kHz | `SysTick_Handler → xPortSysTickHandler()` |
| LVGL | SysTick（通过 FreeRTOS tick） | 1kHz | `lv_tick_set_cb(app_lvgl_tick_get_ms)`，回调返回 `xTaskGetTickCount()` |

- **LVGL tick**：通过 `lv_tick_set_cb()` 绑定 `xTaskGetTickCount()`，直接使用 SysTick 的 1ms 节拍；任务循环只调用 `lv_timer_handler()`，不再累加 `lv_tick_inc()`。这样即使 `lv_timer_handler()` 耗时超过 5ms，也不会少算真实时间，动画与 `lv_timer` 不会整体变慢。
- **显示与加速时钟**：LTDC 像素时钟由 **PLLSAI** 提供（N=307、R=3、DivR=2 → 25M/25×307/3/2 ≈ **51.17MHz**，见 `Core/Src/ltdc.c`），1344×635 总时序对应约 60Hz，匹配 ATK-7016 的 51.2MHz 规格；DMA2D 挂 AHB，时钟 HCLK=216MHz。DMA2D 与 LTDC 共用 SDRAM 总线，带宽争用是画面抖动/丢点的排查项之一。

### 2.2 LVGL 帧缓冲与 FMC 时序

帧缓冲位于外部 SDRAM（FMC Bank1，基址 `0xC0000000`），LTDC 扫描该缓冲，LVGL 使用内部 SRAM 局部缓冲并在 flush 时更新。SDRAM 控制器与芯片时序在 `Core/Src/fmc.c` 中配置，本节数值即取自该文件，**改代码后须同步更新本文**。

**器件与控制器参数（`hsdram1.Init`）**

| 参数 | 值 | 说明 |
|------|----|------|
| `SDBank` | `FMC_SDRAM_BANK1` | 帧缓冲映射到 `0xC0000000` |
| `ColumnBitsNumber` | `FMC_SDRAM_COLUMN_BITS_NUM_9` | 列地址 9 位 |
| `RowBitsNumber` | `FMC_SDRAM_ROW_BITS_NUM_13` | 行地址 13 位 |
| `MemoryDataWidth` | `FMC_SDRAM_MEM_BUS_WIDTH_16` | 16 位数据总线 |
| `InternalBankNumber` | `FMC_SDRAM_INTERN_BANKS_NUM_4` | 器件内部 4 Bank |
| `CASLatency` | `FMC_SDRAM_CAS_LATENCY_3` | CAS = 3 |
| `SDClockPeriod` | `FMC_SDRAM_CLOCK_PERIOD_2` | **SDCLK = HCLK/2 = 108MHz**（HCLK=216MHz） |
| `ReadBurst` | `FMC_SDRAM_RBURST_ENABLE` | 使能读突发 |
| `ReadPipeDelay` | `FMC_SDRAM_RPIPE_DELAY_1` | 读管道延迟 1 周期 |
| `WriteProtection` | `FMC_SDRAM_WRITE_PROTECTION_DISABLE` | 关闭写保护 |

**时序寄存器（`SdramTiming`，单位：SDCLK 周期 @108MHz）**

| 字段 | 值 | 对应参数 |
|------|----|---------|
| `LoadToActiveDelay` | 2 | TMRD（加载模式寄存器→激活） |
| `ExitSelfRefreshDelay` | 8 | TXSR（退出自刷新） |
| `SelfRefreshTime` | 6 | TRAS（自刷新/行激活） |
| `RowCycleDelay` | 6 | TRC（行周期） |
| `WriteRecoveryTime` | 2 | TWR（写恢复，与正点原子同板参考驱动一致；SWD 发现旧值 16 会显著加重 DCMI/LTDC 的 SDRAM 写等待） |
| `RPDelay` | 2 | TRP（预充电） |
| `RCDDelay` | 2 | TRCD（行→列） |

**上电初始化序列（`MX_FMC_Init()` 的 USER CODE 2 区）**

`HAL_SDRAM_Init()` 只配置 FMC 控制器，**不执行 SDRAM 芯片的上电命令时序**，须在 `MX_FMC_Init()` 的 USER CODE 2 区手动补齐；缺此序列时帧缓冲未初始化，LTDC 读回异常导致 LCD 黑屏：

1. `FMC_SDRAM_CMD_CLK_ENABLE`（CKE 拉高）→ `HAL_Delay(1)`（芯片要求 ≥100µs，1ms 足够）；
2. `FMC_SDRAM_CMD_PALL`（Precharge All）；
3. `FMC_SDRAM_CMD_AUTOREFRESH_MODE`，`AutoRefreshNumber = 8`；
4. `FMC_SDRAM_CMD_LOAD_MODE`，模式寄存器值 **`0x230`**（CAS=3 | 顺序突发 | Burst Length=1）；
5. `HAL_SDRAM_ProgramRefreshRate(&hsdram1, 824)` —— 由 `refresh = 64ms / 8192 行 × f(SDCLK) − 20` 得出（108MHz → 1056 − 20 ≈ **824**）。

> 该序列必须在 `MX_LTDC_Init()` 之前完成（`main.c` 中 `MX_FMC_Init()` 已移到 LTDC 之前）；LTDC 一旦使能 layer0 就会持续扫描 `0xC0000000`，SDRAM 未初始化时会出现全屏条纹/花屏。

**SDRAM 地址分配（Bank1，基址 `0xC0000000`，器件 32MB）**

| 区域 | 起始地址 | 大小 | 用途 |
|------|----------|------|------|
| LVGL layer0 帧缓冲 | `0xC0000000` | 1024×600×2 = 1228800 B 预留 | LTDC 全屏扫描；竖屏旋转写入 |
| 相机 FB0 / FB1 / FB2 | `0xC0140000` / `0xC0200000` / `0xC02C0000` | 各 512×512×2 = 524288 B | LTDC 第二图层扫描，三缓冲轮换 |

本文只分配 LVGL 帧缓冲；相机三块缓冲的分配与使用见《04.DCMI摄像头模块方案.md》，两者不得重叠。

其余要点：

- **颜色深度必须与 LTDC 像素格式一致（RGB565 / 16 位 / 2 字节）**：LVGL v9 由 `LV_COLOR_FORMAT_DEFAULT` 配置（`lv_conf.h` 中已设为 `LV_COLOR_FORMAT_RGB565`），内部 `LV_COLOR_DEPTH` 据此推导为 16。flush 拷贝按 16 位像素计算，不一致会越界/花屏。实施时务必核对 `lv_conf.h` 中 `LV_COLOR_FORMAT_DEFAULT` 为 `LV_COLOR_FORMAT_RGB565`。
- `LV_USE_OS = LV_OS_NONE`：LVGL 在调用 `lv_timer_handler()` 的任务上下文内同步渲染，不创建独立渲染线程，也不使用跨线程信号量；这是规避 swdraw 握手死锁的最终配置（见第 8 节问题 4）。
- 关闭/裁剪 `examples` 与 `demos`。

### 4.3 显示移植层 `LVGL/lv_port_disp.c`（LTDC + SDRAM，PARTIAL + DMA2D）

LTDC 由 DMA 持续从 SDRAM 扫描输出，不需要按块搬送。核心实现：

```c
#define LV_PORT_DISP_FB_ADDR   ((void *)0xC0000000UL)   /* 外部 SDRAM Bank1 基址，按 1024x600 上限预留 */
#define LV_PORT_DISP_PHYS_W    1024
#define LV_PORT_DISP_PHYS_H    600
#define LV_PORT_DISP_ROTATION  LV_DISPLAY_ROTATION_270
#define LV_PORT_DRAW_BUF_PIXELS (1024U * 32U)
static uint16_t s_drawBuf[LV_PORT_DRAW_BUF_PIXELS] LV_ATTRIBUTE_MEM_ALIGN
    __attribute__((aligned(32)));      /* DMA2D 源，32B 对齐 */

/* 等待 DMA2D 空闲：带 50ms 超时，超时就强制停流并清全部错误标志，
   避免残留传输和下一次配置打架（旧版是死等 + 只清 TC） */
static void lv_port_dma2d_wait(void)
{
    uint32_t startTick = HAL_GetTick();

    while ((DMA2D->CR & DMA2D_CR_START) != 0U) {
        if ((HAL_GetTick() - startTick) > LV_PORT_FLUSH_TIMEOUT_MS) {
            DMA2D->CR &= ~DMA2D_CR_START;
            break;
        }
    }
    DMA2D->IFCR = DMA2D_FLAG_TC | DMA2D_FLAG_TE | DMA2D_FLAG_CE |
                  DMA2D_FLAG_CAE | DMA2D_FLAG_CTC | DMA2D_FLAG_TW;
}

/* PARTIAL 模式：px_map 位于内部 SRAM，flush 由 DMA2D 写入 LTDC 帧缓冲 */
static void lv_port_disp_flush_cb(lv_display_t *disp, const lv_area_t *area, uint8_t *px_map)
{
    uint32_t width  = (uint32_t)(area->x2 - area->x1 + 1);
    uint32_t height = (uint32_t)(area->y2 - area->y1 + 1);
    uint32_t stride = (uint32_t)lv_display_get_horizontal_resolution(disp);
    uint32_t dst    = (uint32_t)LV_PORT_DISP_FB_ADDR +
                      ((((uint32_t)area->y1 * stride) + (uint32_t)area->x1) * 2U);

    /* DMA2D 不做 D-Cache 一致性维护：像素是 CPU 刚写进 s_drawBuf 的，
       若 D-Cache 打开，脏行可能还没写回 SRAM，DMA2D 会读到旧像素 */
    SCB_CleanDCache_by_Addr((uint32_t *)px_map, (int32_t)(width * height * 2U));
    __DSB();

    lv_port_dma2d_wait();
    DMA2D->CR = DMA2D_M2M;
    DMA2D->OOR = stride - width;
    DMA2D->FGOR = 0;
    DMA2D->FGPFCCR = DMA2D_INPUT_RGB565;
    DMA2D->OPFCCR = DMA2D_OUTPUT_RGB565;
    DMA2D->FGMAR = (uint32_t)px_map;
    DMA2D->OMAR = dst;
    /* NLR: [15:0] = 行数，[29:16] = 每行像素数 */
    DMA2D->NLR = (width << DMA2D_NLR_PL_Pos) |
                 (height << DMA2D_NLR_NL_Pos);
    DMA2D->CR = DMA2D_M2M | DMA2D_CR_START;
    lv_port_dma2d_wait();
    lv_display_flush_ready(disp);
}

void lv_port_disp_init(void)
{
    lv_display_t *disp = lv_display_create(LV_PORT_DISP_PHYS_W, LV_PORT_DISP_PHYS_H);
    if(disp == NULL) return;

    s_disp = disp;
    lv_display_set_color_format(disp, LV_COLOR_FORMAT_RGB565);
    lv_display_set_rotation(disp, LV_PORT_DISP_ROTATION);

    /* 内部 SRAM 局部缓冲：渲染与 LTDC 扫描解耦 */
    lv_display_set_buffers(disp, s_drawBuf, NULL,
                           sizeof(s_drawBuf), LV_DISPLAY_RENDER_MODE_PARTIAL);

    lv_display_set_flush_cb(disp, lv_port_disp_flush_cb);
    lv_display_set_default(disp);
}
```

显示初始化、启动动画和主界面始终使用固定的 **600×1024** 逻辑画布，不再动态切换显示区域。

前提：SDRAM 已由 `MX_FMC_Init()` 完成上电初始化，LTDC layer0 指向 `0xC0000000`。LVGL 先在内部 SRAM 完成局部渲染，DMA2D 再把连续区域复制到 SDRAM；这样避免 CPU 长时间占用 FMC。

> **PARTIAL + 旋转 flush 的目的**：CPU 先在内部 SRAM 完成竖屏局部渲染，再按逻辑到物理坐标映射旋转写入 SDRAM。DMA2D 不支持 90° 旋转，因此当前竖屏路径不使用 DMA2D；无旋转路径仍保留原 DMA2D 实现。

（SDRAM 控制器参数、时序寄存器与上电初始化序列见 §2.2，配置位于 `Core/Src/fmc.c`。）

### 4.4 输入移植层 `LVGL/lv_port_indev.c`

`lv_port_indev_init()` 先调用 `Touch_Detect()` 探测 GT9xxx 并打印 `[TOUCH] GT9xxx detected / not found`，再注册指针型输入设备；read 回调调用 `Touch_Scan()` 返回真实坐标，详见《03.触摸移植方案.md》。

```c
void lv_port_indev_init(void)
{
    lv_indev_t *indev;
    uint8_t detected = Touch_Detect();

    AppUart_Printf("[TOUCH] GT9xxx %s\r\n", (detected != 0U) ? "detected" : "not found");

    indev = lv_indev_create();
    lv_indev_set_type(indev, LV_INDEV_TYPE_POINTER);
    lv_indev_set_read_cb(indev, lv_port_indev_read_cb);
}

static void lv_port_indev_read_cb(lv_indev_t * indev, lv_indev_data_t * data)
{
    uint16_t x = 0;
    uint16_t y = 0;

    (void)indev;

    if(Touch_Scan(&x, &y) != 0U)
    {
        data->state = LV_INDEV_STATE_PRESSED;
        lv_point_t point = { .x = x, .y = y };
        lv_display_rotate_point_ccw(lv_display_get_default(), &point);
        data->point = point;
    }
    else
    {
        data->state = LV_INDEV_STATE_RELEASED;
    }

    data->continue_reading = false;
}
```

> 触摸芯片为 GT1151（软件 I2C，0x5D），原始坐标为 1024×600。输入回调保持上报物理坐标，由 LVGL v9 输入层根据 `LV_DISPLAY_ROTATION_270` 自动转换到 600×1024 逻辑坐标；不要在回调中再次旋转。

### 4.5 应用任务 `App/lvgl/app_lvgl.c`

任务主体：单次完成 LVGL 及各移植层初始化，随后周期调用 `lv_timer_handler()` 推进渲染，配合 `vTaskDelay` 让出 CPU：

```c
/* LVGL tick 取 FreeRTOS SysTick（configTICK_RATE_HZ=1000，1 tick = 1ms） */
static uint32_t app_lvgl_tick_get_ms(void)
{
    return (uint32_t)xTaskGetTickCount();
}

static void AppLvgl_Task(void * param)
{
    (void)param;

    lv_init();                             /* LVGL 初始化，仅在本任务内调用一次 */
    lv_tick_set_cb(app_lvgl_tick_get_ms);  /* 绑定 SysTick，替代 lv_tick_inc */
    lv_port_disp_init();
    lv_port_indev_init();

    /* 先显示全屏安全自检动画，100% 后自动销毁并构建授权界面 */
    app_lvgl_splash_create();

    AppUart_Printf("[LVGL] portrait face-auth UI ready, 600x1024\r\n");

    for (;;)
    {
        lv_timer_handler();                         /* 渲染与事件处理 */
        vTaskDelay(pdMS_TO_TICKS(APP_LVGL_PERIOD_MS));
    }
}
```

**启动加载动画**（`app_lvgl_splash_create()` + `splash_timer_cb()`）：

- 进度条每 **25ms +4%**（约 0.65s 走完），文案按进度切换：显示就绪 → 输入就绪 → 相机就绪 → 进入界面；
- 到 100% 时删除定时器与加载页 → `app_lvgl_ui_create()` 构建竖屏授权界面，并注册 500ms 设备异常刷新定时器。

- DMA2D 初始化：当前演示阶段 `LV_USE_DRAW_DMA2D=0`，`lv_init()` 不注册 DMA2D draw unit；确认 LTDC/SDRAM 显示正常后再置 1，此时 `lv_init()` 会自动调用 `lv_draw_dma2d_init()`，应用代码不要重复调用（见 §4.7.3）。
- 竖屏授权界面 `app_lvgl_ui_create()` 使用 `app_font_cn_14.c` 与 `app_font_cn_24.c`：顶部为 512×512 预览位；中部为当前状态和 160×160 环形进度；底部显示“开始上机 → 开始拍照 → 开始验证”三步位置和唯一主按钮。拍照后进入确认状态，用户点击“开始验证”才启动验证进度。
- 任务参数在 `App/app_config.h` 集中配置：

  ```c
  #define APP_LVGL_TASK_PRIORITY        4
  #define APP_LVGL_TASK_STACK_SIZE      ( 32 * configMINIMAL_STACK_SIZE )  /* 渲染递归较深，栈需给足 */
  #define APP_LVGL_PERIOD_MS            5     /* lv_timer_handler 调用周期 */
  ```

  栈分配过小时，LVGL `lv_init/open` 渲染递归深会触发 `configCHECK_FOR_STACK_OVERFLOW=2` 死循环，表现为整机卡死黑屏。

- 在 `App/app_tasks.c` 注册一行：`AppLvgl_TaskCreate();`。

### 4.7 DMA2D 绘制加速（LVGL draw unit）

DMA2D 作为 LVGL v9 的一个 draw unit 参与渲染。它只接管满足条件的任务：无圆角、无渐变的填充，以及无遮罩、无缩放/旋转、无重着色、源为变量图像的图片；文本、圆角、渐变等仍由 `LV_USE_DRAW_SW` 软件渲染处理。DMA2D 只加速 LVGL 绘制；相机画面由 LTDC 图层 2 直接扫描，不做软件旋转，见《04.DCMI摄像头模块方案.md》。

#### 4.7.1 源码补齐

项目内的 `LVGL/lvgl/src/draw/dma2d/` 原只有头文件（lite 快照缺少实现），现已从参考副本补齐：

| 目标 | 来源 |
|------|------|
| `LVGL/lvgl/src/draw/dma2d/lv_draw_dma2d.c` | `Docs/lvgl-v9.6.0-lite/src/draw/dma2d/lv_draw_dma2d.c` |
| `LVGL/lvgl/src/draw/dma2d/lv_draw_dma2d_fill.c` | 同目录 |
| `LVGL/lvgl/src/draw/dma2d/lv_draw_dma2d_img.c` | 同目录 |

补齐后把 3 个 `.c` 加入 `MDK-ARM` 的 `Middleware/LVGL` 组；只复制头文件会在链接阶段报 `lv_draw_dma2d_init` / `lv_draw_dma2d_fill` / `lv_draw_dma2d_image` 未定义。

#### 4.7.2 `lv_conf.h`

以下为确认 LTDC/SDRAM 显示正常、准备启用 DMA2D 时的配置；演示阶段保持 `LV_USE_DRAW_DMA2D=0`。

```c
#define LV_USE_DRAW_DMA2D            1
#define LV_DRAW_DMA2D_HAL_INCLUDE    "stm32f7xx_hal.h"  /* F7 工程；模板默认的 H7 头会导致编译失败 */
#define LV_USE_DRAW_DMA2D_INTERRUPT  0  /* LV_OS_NONE 下必须为 0 */
```

- `LV_USE_DRAW_SW` 保持 1，作为不支持任务的回退。
- `LV_USE_DRAW_DMA2D_INTERRUPT` 只有在 `LV_USE_OS != LV_OS_NONE` 时才能置 1；置 1 后必须提供 `DMA2D_IRQHandler()`，并在其中调用 `lv_draw_dma2d_transfer_complete_interrupt_handler()`。
- 当前 `LV_OS_NONE` 使用同步等待（轮询 `DMA2D->CR.START`），不产生 DMA2D 中断。

#### 4.7.3 初始化顺序

```c
/* main.c：调度器启动前 */
MX_DMA2D_Init();          /* M2M / RGB565 / LayerCfg[1]=RGB565 */

/* App/lvgl/app_lvgl.c：LVGL 任务内 */
lv_init();                /* LV_USE_DRAW_DMA2D=1 时内部自动调用 lv_draw_dma2d_init() */
lv_tick_set_cb(app_lvgl_tick_get_ms);
lv_port_disp_init();
lv_port_indev_init();
```

`lv_draw_dma2d_init()` 由 `lv_init()` 自动调用（见 `lv_init.c` 的 `#if LV_USE_DRAW_DMA2D` 分支），应用层不要再调用一次，否则会重复注册 draw unit。它与 `MX_DMA2D_Init()` 都会使能 DMA2D 时钟，重复使能无副作用；但不要在两处同时发起 DMA2D 传输。

#### 4.7.4 DMA2D 参数（`MX_DMA2D_Init()`）

| 参数 | 值 | 约束 |
|------|----|------|
| Mode | `DMA2D_M2M` | 基础模式；fill/image 由 draw unit 按任务切换 |
| ColorMode | `DMA2D_OUTPUT_RGB565` | 必须与 LTDC 图层像素格式一致 |
| OutputOffset | 0 | 全屏 layer0；子区域绘制时由 LVGL 按 stride 计算，不能硬编码为 0 |
| LayerCfg[1].InputColorMode | `DMA2D_INPUT_RGB565` | 与源图格式一致 |
| AlphaMode | `DMA2D_NO_MODIF_ALPHA` | 不透明源；混合任务由 draw unit 重新配置 |
| 地址对齐 | RGB565 ≥2 字节 | SDRAM 基址满足；自建缓冲不要放奇地址 |

#### 4.7.5 收益与边界

- 收益：大面积填充、纯色背景与图片搬运从 CPU 转移到 DMA2D，降低 LVGL 任务占用；文本与复杂图形仍走软件渲染。
- 边界：当前 DMA2D 只负责 `flush_cb` 的 RGB565 区域拷贝；LVGL 自身 draw unit 仍关闭，圆角/渐变/遮罩/缩放/旋转/重着色由软件渲染。

## 5. 假设与决策

1. **以 FreeRTOS 成功移植为前提**，LVGL 复用其任务调度与 heap；不做任何 FreeRTOS 二次改动。
2. 目录镜像官方 `LVGL/lvgl/` 结构并置于根目录 `LVGL/`，便于对照官方源码定位与升级。
3. LTDC 帧缓冲必须放外部 SDRAM（预留 1.2 MB，另加相机 3×663552 B）；LVGL 使用 64KB 内部 SRAM 局部渲染缓冲，DMA2D 负责写入显存。
4. 颜色格式必须与 RGB565 一致（`LV_COLOR_FORMAT_DEFAULT = LV_COLOR_FORMAT_RGB565`，16 位）。flush 按像素字节数计算，不一致会越界/花屏。
5. LVGL 采用单任务内联渲染（`LV_OS_NONE`），不引入 CMSIS-RTOS，也不创建 swdraw 渲染线程。
6. 触摸读取在 LVGL 输入回调内完成，不得阻塞 LVGL 主循环（软件 I2C 单次读取 < 1ms）。
7. DMA2D draw unit 已接入；演示阶段暂关闭，确认 LTDC/SDRAM 显示链路后再启用。启用后不支持的任务由软件渲染回退。
8. 允许把已验证的 LTDC / FMC / DMA2D 配置回填到 `.ioc`；回填后由 CubeMX 重新生成并复核 USER CODE 区。

## 8. 实施中遇到的问题与修正

以下为实测中遇到的编译、集成问题的修复记录。

### 问题 1：`'fs/lv_fs_private.h' file not found`

- 现象：编译 `lv_init.c`、`lv_fs.c` 报 `fs/lv_fs_private.h` / `lv_fs_private.h` 找不到。
- 原因：LVGL 源码中 `lv_init.c`（第 24 行）与 `lv_fs.c`（第 10 行）**无条件引用私有头** `lv_fs_private.h`，靠「引号包含优先查源文件所在目录」解析；而 lite 快照的 `src/fs/` 只带了 `lv_fs.c`，**打包漏掉了 `lv_fs_private.h`**。
- 修复：从参考副本 `Docs/lvgl-v9.6.0-lite/src/fs/lv_fs_private.h` 复制补齐至 `LVGL/lvgl/src/fs/lv_fs_private.h`。已扫描 `LVGL/lvgl/src/` 下所有 `.c` 引用的 `_private.h`，现全部可解析。

### 问题 2：uvprojx 在 Keil 中无法打开

- 现象：工程文件双击打开失败。
- 原因：脚本改动路径时被写成了 **带 UTF-8 BOM** 的编码，与 Keil 原始**无 BOM** 文件不一致。
- 修复：以无 BOM 的 UTF-8 重写 uvprojx（首字节 `3C 3F`），并复验为良构 XML、分组完整。

### 问题 3：第一次 `lv_timer_handler()` 渲染 HardFault（LVGL 内存池不足）

- 现象：LVGL 初始化、demo 创建均成功，但第一次 `lv_timer_handler()` 进入渲染/动画定时器时 HardFault；屏幕只显示 SDRAM 残留的红色背景，LVGL 界面不出现。
- 根因：`LV_MEM_SIZE = 16KB` 内存池不足以创建 demo 的 30+ 控件（chart 60 点、scale 21 刻度等），某控件 `lv_malloc` 失败返回 NULL；`LV_USE_ASSERT = 0` 不拦截，200ms 自走动画定时器（`lv_timer_ready` 首帧立即执行）回调解引用 NULL 句柄 → HardFault。
- 定位方法：`lv_timer_handler()` 前后加裸机直发打印（`AppUart_BarePrint`），确认崩溃点在 handler 内部；`HardFault_Handler` 打印 CFSR/BFAR，若 BFAR=0 即确认 NULL 解引用。
- 修复（三处联动调大，F767IGT6 共 512KB 内部 SRAM，调整后余量仍充足）：

  | 文件 | 配置项 | 原值 | 新值 |
  |------|--------|------|------|
  | `LVGL/lv_conf.h` | `LV_MEM_SIZE` | 16384（16KB） | **65536（64KB）** |
  | `FreeRTOS/Config/FreeRTOSConfig.h` | `configTOTAL_HEAP_SIZE` | 32KB | **64KB**（各任务栈与运行期对象共用） |
  | `App/app_config.h` | `APP_LVGL_TASK_STACK_SIZE` | 16 × `configMINIMAL_STACK_SIZE` | **32 ×**（渲染递归深） |

- 附带清理：修复确认后删除全部串口诊断插桩（app_lvgl.c 的 `[LVGL]`/`[FLUSH]`/alive 打印、`HardFault_Handler` 寄存器打印、`vApplicationStackOverflowHook` 打印、touch_detect 的 I2C 地址扫描及其 `AppUart_BarePrint` 接口）。

### 问题 4：`LV_OS_FREERTOS` 下画面冻结、`lv_timer_handler()` 永久阻塞

- 现象：界面首次渲染正常，随后动画停止、触摸无响应、无 alive 日志，任务不 HardFault 也不复位。
- 根因：`LV_OS_FREERTOS` 会创建独立的 swdraw 软件渲染线程，用任务通知做绘制握手（单槽位 `xTaskToNotify` + 单标志 `xSyncSignal`）。渲染线程与 LVGL 任务在 1kHz tick 下发生特定调度交错时通知会丢失，等待侧 `ulTaskNotifyTake(portMAX_DELAY)` 永久阻塞，主任务随后卡在 `lv_timer_handler()`。
- 修复：`LVGL/lv_conf.h` 的 `LV_USE_OS` 改为 `LV_OS_NONE`，渲染回到 LVGL 任务内同步执行，不再有跨线程握手。代价是渲染期间该任务不让出 CPU；当前 5ms 周期 + 局部刷新可以接受（对应提交 `fix(lvgl): 关闭 swdraw 渲染线程避免绘制握手死锁`）。

### 其他注意

- 颜色格式（`LV_COLOR_FORMAT_DEFAULT`）与像素格式务必一致；LTDC 全屏缓冲须常驻，内部 SRAM 局部缓冲不可与栈/heap重叠。
- LVGL 任务栈按 `16 × configMINIMAL_STACK_SIZE` 起步（渲染递归深），过小会栈溢出死循环；实测调大至 `32 ×`（见问题 3）。
- DMA2D 接入后若出现花屏/抖动，按 §9 排查；不要先改 LVGL 配置或 DMA2D 参数。

## 9. 问题说明：花屏、抖动与撕裂

**排查顺序固定为：LTDC 时序 → SDRAM/FMC → DMA2D → LVGL 缓冲。** 不要一上来改 LVGL 或 DMA2D 参数；显示链路的基础时序不对时，上层怎么调都会花屏。摄像头相关的花屏/横带错位在后续摄像头阶段排查。

### 9.1 第一步：LTDC 时序

`ltdc.c` 里存的是 LTDC 寄存器值（宽度/累计值减 1）；实际时序按宽度描述时，寄存器值 = 实际宽度 − 1，不能把实际宽度直接抄进 HAL 结构体：

| HAL 字段 | `ltdc.c` 值 | 与实际宽度的关系 |
|----------|-------------|------------------|
| `HorizontalSync` | 19 | HSync=20 → 寄存器 19 |
| `VerticalSync` | 2 | VSync=3 → 寄存器 2 |
| `AccumulatedHBP` | 159 | HSync+HBP−1 = 20+140−1 |
| `AccumulatedVBP` | 22 | VSync+VBP−1 = 3+20−1 |
| `AccumulatedActiveW` | 1183 | HSync+HBP+ActiveW−1 |
| `AccumulatedActiveH` | 622 | VSync+VBP+ActiveH−1 |
| `TotalWidth` | 1343 | HSync+HBP+ActiveW+HFP−1 |
| `TotalHeigh` | 634 | VSync+VBP+ActiveH+VFP−1 |

检查项：

- PLLSAI 像素时钟（N=360、R=2、DivR=4）是否为 45MHz。
- HSPolarity / VSPolarity / DEPolarity / PCPolarity 是否为 AL / AL / AL / IPC。
- 图层 0 窗口是否为原生 0~1024 / 0~600，`WindowX1/WindowY1` 为右开区间。
- 先用纯色或棋盘格测试：不启动 LVGL、不启用 DMA2D，确认显示链路本身无误，再逐项打开。

典型现象对照：

| 现象 | 优先检查 |
|------|----------|
| 整屏水平/垂直偏移、边缘黑边 | HBP/HFP/VBP/VFP、Accumulated 值、TotalWidth/TotalHeigh |
| 画面抖动、刷新率不稳 | PLLSAI 像素时钟、SDRAM 时序/刷新率、LTDC 与 DMA2D 带宽争用 |
| 彩色条纹、局部块错位 | SDRAM/FMC 时序、DMA2D 输出格式/offset |
| 颜色错误（红蓝互换/发灰） | RGB565 与 ARGB8888 混用、DMA2D `ColorMode`/`InputColorMode` |
| 局部撕裂 | 检查 PARTIAL flush 区域坐标与 stride；相机区域使用独立图层 2 + 三缓冲 |
| 接入 DMA2D 后卡死 | `LV_USE_DRAW_DMA2D_INTERRUPT=1` 但 `LV_OS_NONE`；缺少 `DMA2D_IRQHandler()`；DMA2D 与 HAL 并发访问 |

### 9.2 第二步：SDRAM/FMC

- CAS=3、SDCLK=108MHz、refresh=824、16 位总线、9 列/13 行/4 Bank，须与 `fmc.c` 一致。
- 上电序列（CLK_ENABLE → PALL → 8×AUTOREFRESH → LOAD_MODE `0x230` → ProgramRefreshRate）缺一不可；缺 CLK_ENABLE/PALL 时 LTDC 读回随机值，表现为整屏花。
- LVGL 帧缓冲与后续相机缓冲不得重叠；相机地址分配在后续摄像头阶段定义。

### 9.3 第三步：DMA2D

- `LV_USE_DRAW_DMA2D_INTERRUPT` 必须与 `LV_USE_OS` 匹配：`LV_OS_NONE` → 0；异步 → 1，且 `LV_USE_OS` 非 NONE、提供 `DMA2D_IRQHandler()`。
- `LV_DRAW_DMA2D_HAL_INCLUDE` 必须是 `"stm32f7xx_hal.h"`；模板默认的 H7 头会让编译直接失败。
- 输出格式与 LTDC 图层一致（RGB565）；`OutputOffset` 由 LVGL 按 stride 计算，子区域绘制时不能硬编码 0。
- RGB565 目标地址至少 2 字节对齐；自建缓冲不要放奇地址。
- DMA2D 与 LTDC 共用 SDRAM 总线；若刷新变慢，先核对 DMA2D 任务粒度与 SDRAM 时序。

### 9.4 第四步：LVGL 缓冲与图层

- `LV_COLOR_FORMAT_DEFAULT` 必须是 `LV_COLOR_FORMAT_RGB565`；PARTIAL 缓冲固定为 1024×32×2 = 65536B，DMA2D flush 目标为 LTDC 的 `0xC0000000`。
- `lv_display_set_buffers()` 的地址必须是 LTDC layer0 的 `0xC0000000`，不能另开内部 SRAM 缓冲。
- 摄像头图层/缓冲（图层 2 + 三缓冲）的排查见《04.DCMI摄像头模块方案.md》§3.7。
